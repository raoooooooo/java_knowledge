# 操作系统

> 📌 **一句话理解**：操作系统面试高频就四块--**进程线程、同步互斥、内存管理、IO 模型**；其中 **IO 多路复用（select/poll/epoll）** 和 **进程线程区别/通信** 是 Java 后端几乎必问的重灾区。

---

## 核心概念

### 一、进程 vs 线程 vs 协程 ⭐⭐⭐⭐⭐

#### 1. 三者对比

| | 进程 | 线程 | 协程 |
|------|------|------|------|
| 资源分配 | 独立地址空间、独占资源 | 共享进程资源 | 共享线程栈 |
| 调度单位 | 操作系统调度 | 操作系统调度 | **用户态**调度 |
| 切换开销 | 大（切页表/上下文） | 中 | 小 |
| 通信方式 | IPC（管道/共享内存等） | 直接共享内存 | 直接共享变量 |
| 并发性 | 低 | 中 | 高 |

**类比理解：**
- **进程** = 工厂，每个工厂有自己的地盘和设备，互不干扰。
- **线程** = 工厂里的工人，共享工厂设备，互相协作。
- **协程** = 工人手上的多个任务，工人自己切换着做，不用惊动工厂管理层（操作系统）。

#### 2. 进程和线程的根本区别

> 🎯 **一句话：进程是资源分配的最小单位，线程是 CPU 调度的最小单位。**

- 进程有**独立的虚拟地址空间**，进程间内存隔离；一个进程崩了不影响别的。
- 线程属于进程，**共享进程的内存**（堆、全局变量、文件描述符等），但各有**私有栈**和寄存器。
- 线程切换比进程便宜，因为不用切地址空间（页表）。

#### 3. 上下文切换开销为什么大？

切换时要把当前运行状态（寄存器、PC、栈指针）保存到 PCB/TCB，再加载下一个的状态。**进程切换还要切页表**（刷 TLB），所以更贵。线程切换在同一地址空间内，省了切页表，但仍要切栈和寄存器。

#### 4. 协程是什么？为什么快？

- 协程是**用户态**的轻量级线程，切换由**程序自己控制**（而非操作系统抢占），不陷入内核态。
- 一个线程里可以有成千上万个协程，切换只需保存寄存器和栈，开销极小。
- 典型：Go 的 goroutine、Java 的虚拟线程（JDK 21 Loom）、Python 的 asyncio。
- **代价**：协程本质是协作式调度，一个协程阻塞会卡住整个线程（所以协程里不能写阻塞 IO，要用非阻塞 IO + 事件循环）。

> 💡 **与 Java 的关系**：JVM 里一个 Java 线程对应一个操作系统线程（1:1 模型）。JDK 21 虚拟线程把大量虚拟线程映射到少量平台线程上（M:N），类似协程，大幅提升并发数。详见 `01-java基础/02-并发编程.md`。

### 二、进程间通信 IPC ⭐⭐⭐⭐

进程内存隔离，要通信必须靠操作系统提供的 IPC 机制：

| 方式 | 特点 | 适用场景 |
|------|------|---------|
| **管道 Pipe** | 半双工、父子进程间；命名管道(FIFO)可无亲缘 | 简单数据流 |
| **消息队列** | 内核中的链表、有格式、按消息读 | 异步通信 |
| **共享内存** | **最快**，多进程映射同一块物理内存 | 大数据量高频通信 |
| **信号量** | 计数器，用于**同步互斥**（不传数据） | 配合共享内存加锁 |
| **信号** | 异步通知（如 SIGKILL/SIGTERM） | 通知事件 |
| **Socket** | 可跨主机、跨网络 | 网络通信 |

**为什么共享内存最快？** 其他 IPC 都要**数据从用户态拷贝到内核态再拷回去**（两次拷贝）；共享内存把同一块物理内存映射到各进程虚拟空间，**直接读写零拷贝**，但需要配合信号量保证同步。

### 三、进程调度算法 ⭐⭐⭐

| 算法 | 思想 | 缺点 |
|------|------|------|
| **FCFS 先来先服务** | 按到达顺序执行 | 短任务被长任务拖累（护航效应） |
| **SJF 短作业优先** | 优先执行预计时间最短的 | 长任务饥饿 |
| **优先级调度** | 按优先级 | 低优先级饥饿（需老化机制） |
| **时间片轮转 RR** | 每个进程给一个时间片，用完排队 | 时间片太大退化 FCFS，太小切换开销大 |
| **多级反馈队列 MLFQ** | 多个优先级队列，动态调整 | 实现复杂，但最实用 |

**多级反馈队列**（现代 OS 主流思想）：
- 新进程进最高优先级队列，用完时间片降级（CPU 密集型会沉底）。
- 主动让出（等 IO）的进程留原级或升级（IO 密集型被优待）。
- 兼顾响应时间（短任务/交互任务先跑）和吞吐量。

### 四、死锁 ⭐⭐⭐⭐⭐

#### 1. 死锁四个必要条件（缺一不可）

1. **互斥**：资源一次只能被一个进程用。
2. **占有并等待**：拿着资源不放，还等新的。
3. **不可剥夺**：资源不能强行抢走，只能等持有者主动释放。
4. **循环等待**：存在进程的环形等待链 A->B->C->A。

#### 2. 死锁处理策略

| 策略 | 做法 |
|------|------|
| **预防** | 破坏四个条件之一（如资源有序分配破坏循环等待） |
| **避免** | 运行时动态判断，**银行家算法**，分配前检查是否安全 |
| **检测与解除** | 允许死锁发生，检测到再杀进程/剥夺资源恢复 |
| **鸵鸟策略** | 忽略不管（多数通用 OS 这么干，概率低） |

#### 3. 银行家算法（避免）

- 思想：分配资源前先模拟分配，判断系统是否处于**安全状态**（存在一个能避免死锁的进程序列）。
- 安全才分配，否则让进程等待。
- 缺点：要提前知道进程最大资源需求，实际难做到，多用于理论/数据库。

#### 4. 预防死锁的常见手段

- **破坏循环等待**：给资源编号，按序申请（如先拿小号再拿大号）。
- **破坏占有并等待**：一次性申请所有资源。
- **破坏不可剥夺**：拿不到就释放已占资源。

> ⚠️ **和 Java 的关系**：Java 里的死锁也满足这四个条件。常用 `jstack` 检测（详见 `02-JVM虚拟机/03-JDK性能监控与故障处理工具.md`）。避免手段：固定锁顺序、加超时 `tryLock`、避免嵌套锁。

### 五、内存管理 ⭐⭐⭐⭐

#### 1. 虚拟内存

- 每个进程有**独立的虚拟地址空间**（如 64 位下理论 2^64），由 OS + MMU 映射到物理内存。
- **好处**：进程隔离（互不踩内存）、内存可超分配（用磁盘 swap 兜底）、简化编程（连续虚拟空间）。

#### 2. 分页（Paging）⭐

- 把虚拟内存和物理内存切成固定大小的**页**（如 4KB）。
- 用**页表**记录虚拟页 -> 物理页的映射。
- 优点：无外部碎片。缺点：有内部碎片（最后一页用不满）、页表占内存。

#### 3. TLB（快表）与多级页表

- **TLB（Translation Lookaside Buffer）**：页表的高速缓存（CPU 内），命中就不用查内存里的页表，大幅加速地址翻译。
- **多级页表**：64 位地址空间页表巨大，用多级页表 + **只分配用到的部分**，省内存。

#### 4. 分段（Segmenting）vs 段页式

- **分段**：按逻辑单元（代码段/数据段/栈段）划分，大小不固定。优点符合程序逻辑，缺点有外部碎片。
- **段页式**：先分段再分页，结合两者。现代多用纯分页。

#### 5. 页面置换算法 ⭐⭐⭐（高频）

内存满了要换出某页，选哪个换？

| 算法 | 思想 | 评价 |
|------|------|------|
| **OPT 最佳置换** | 换未来最久不用的 | 理论最优，**无法实现**（要预知未来） |
| **FIFO 先进先出** | 换最早进来的 | 简单，但有 **Belady 异常**（页框增多缺页反而增多） |
| **LRU 最近最久未用** | 换最久没访问的 | 性能好，接近 OPT；实现要记录访问时间 |
| **LFU 最少使用** | 换访问次数最少的 | 适合热点稳定的场景 |
| **Clock 时钟算法** | LRU 的近似，用访问位环形扫描 | 工程常用，开销小 |

> 💡 **LRU 怎么实现？** 经典：**哈希表 + 双向链表**。访问节点移到链表头，淘汰时删链表尾。Redis 的内存淘汰策略、Java `LinkedHashMap` 的 `accessOrder=true` 都是这个思路。

### 六、线程同步与互斥 ⭐⭐⭐⭐

多线程共享内存，并发访问会出问题，需要同步机制：

| 机制 | 作用 | 注意 |
|------|------|------|
| **互斥锁 Mutex** | 同一时刻只允许一个进入临界区 | 会睡眠，切换开销 |
| **自旋锁 Spinlock** | 拿不到就忙等（自旋）不睡眠 | 适合临界区极短，避免睡眠开销；长临界区浪费 CPU |
| **读写锁** | 读可共享、写独占 | 读多写少场景 |
| **条件变量** | 等待某条件成立才继续，配合互斥锁 | 生产者-消费者 |
| **信号量 Semaphore** | 计数器控制同时访问数 | 可用于资源池限流 |

**互斥锁 vs 自旋锁（常问）：**
- 互斥锁拿不到就**阻塞睡眠**，让出 CPU；唤醒有上下文切换开销。适合临界区长、持有时间不确定。
- 自旋锁拿不到就**死循环忙等**，不让出 CPU；没有切换开销。适合临界区极短（几个指令），且预计很快能拿到。

> ⚠️ **自旋锁的坑**：单核下自旋锁可能死等（持有者需要 CPU 才能释放，但被自旋者占着）；多核才有意义。临界区长时用自旋锁会烧 CPU。

### 七、IO 模型 ⭐⭐⭐⭐⭐（重灾区）

#### 1. 先理清四个概念（极易混）

| | 阻塞 | 非阻塞 |
|------|------|------|
| **同步** | BIO（一直等） | NIO 轮询（一直问，CPU 空转） |
| **异步** | - | AIO（做完通知你） |

- **阻塞/非阻塞**：调用 IO 后线程**是否挂起等待**。阻塞 = 卡住不干别的；非阻塞 = 立刻返回，数据没好就返回错误，要自己轮询。
- **同步/异步**：数据准备好后**谁来读**。同步 = 自己读（哪怕非阻塞也得自己调 read）；异步 = 内核读好后通知你（数据已拷到用户区）。

> ⎈ **一句话区分**：阻塞非阻塞说的是**调用方**要不要等；同步异步说的是**数据搬运**谁干（应用自己搬=同步，内核搬好通知=异步）。

#### 2. 五种 IO 模型

1. **阻塞 IO（BIO）**：调 recvfrom 一直等到数据 copy 完成。一个连接一个线程。
2. **非阻塞 IO**：recvfrom 没数据立刻返回 EWOULDBLOCK，循环轮询。CPU 空转。
3. **IO 多路复用**：一个线程**同时监听多个 fd**，哪个就绪处理哪个。select/poll/epoll。
4. **信号驱动 IO**：内核数据就绪发 SIGIO 信号，应用再去读。少用。
5. **异步 IO（AIO）**：应用发起请求就不管了，内核**把数据拷到用户缓冲区**完成后通知。真正的异步。Linux 的 AIO（io_uring/POSIX AIO）支持有限，Windows IOCP 是成熟的真异步。

#### 3. IO 多路复用 select / poll / epoll ⭐⭐⭐⭐⭐（必考）

**解决的问题：一个线程管理大量连接，不用一个连接一个线程。**

| | select | poll | epoll |
|------|------|------|------|
| 数据结构 | bitmap | 链表 | **红黑树 + 就绪链表** |
| fd 上限 | 1024（FD_SETSIZE） | 无上限 | 无上限 |
| 复制开销 | 每次调用全量拷贝 fd 集合到内核 | 同 select | epoll_ctl 增量注册，epoll_wait 不拷贝 |
| 就绪检测 | **遍历全部** fd 线性 O(n) | 遍历全部 O(n) | **只返回就绪的** O(1)~O(就绪数) |
| 触发方式 | LT | LT | **LT + ET** 可选 |
| 性能 | 连接多时差 | 略好 | 连接多时最优 |

**epoll 三个核心 API：**
- `epoll_create`：创建 epoll 实例（内核建红黑树）。
- `epoll_ctl`：注册/修改/删除关注的 fd（插入红黑树）。
- `epoll_wait`：阻塞等待，**只返回就绪的 fd**（从就绪链表取）。

**epoll 为什么快？**
1. **不每次全量拷贝** fd 集合（select/poll 的痛点），增删改是 epoll_ctl 一次。
2. **不遍历全部 fd**，只处理就绪的。通过**回调机制**：fd 就绪时内核回调把它加到就绪链表，epoll_wait 直接取链表。

**LT（水平触发）vs ET（边缘触发）：**
- **LT**（默认）：只要 fd 有数据可读，每次 epoll_wait 都会通知你（你没读完会一直通知）。**稳妥**，不易漏。
- **ET**：只在状态变化时通知**一次**（从无数据变有数据），必须一次性读完所有数据（配合非阻塞 IO + 循环读到 EAGAIN），否则丢事件。**效率更高**，但编程复杂、易出错。

> 💡 **Nginx/Netty/Redis 都用 epoll**。Nginx 用 epoll + ET；Redis 单线程却能扛高并发靠的就是 epoll IO 多路复用（详见 `06-中间件/04-Nginx.md`）。Java NIO 在 Linux 底层也是 epoll。

#### 4. Reactor 模式

基于 IO 多路复用的**事件驱动**设计模式，Netty/Redis/Nginx 都用：

- **Reactor**：主线程跑 epoll_wait 监听连接事件/IO 事件，分发。
- **Acceptor**：处理新连接。
- **Handler**：处理已就绪连接的读写业务。

三种变体：
- **单 Reactor 单线程**：一个线程全干（Redis 6.0 前）。
- **单 Reactor 多线程**：Reactor 只接发，业务丢给线程池。
- **主从 Reactor**（Netty 默认）：主 Reactor 接连接，从 Reactor 处理 IO，业务丢线程池。

> 与 Java 的关系详见 `01-java基础/03-IO与NIO.md`、`06-中间件/04-Nginx.md`。

### 八、用户态与内核态 ⭐⭐⭐

#### 1. 为什么要分两个态？

- **内核态**：特权级高，能访问所有硬件和内存，执行操作系统内核代码。
- **用户态**：应用运行的态，权限受限，不能直接碰硬件/内核内存，**保证安全**。
- 应用要读文件、发网络请求、创建线程，都要**系统调用**陷入内核态由内核代劳。

#### 2. 什么时候切换到内核态？

1. **系统调用**（主动）：read/write/socket/fork 等。
2. **异常**（被动）：缺页异常、除零等。
3. **硬件中断**（被动）：磁盘 IO 完成、网卡收到包触发中断。

#### 3. 切换的代价

用户态 <-> 内核态切换要**保存/恢复寄存器、切栈、权限切换**，开销不小。所以：
- 频繁系统调用要优化（如用批处理减少次数）。
- **零拷贝**技术就是为减少用户态/内核态切换和拷贝。

#### 4. 零拷贝（与 Kafka 关联）⭐⭐⭐

传统读文件发网络：**4 次拷贝 + 4 次上下文切换**。

```
磁盘 →(DMA)→ 内核缓冲 →(CPU)→ 用户缓冲 →(CPU)→ Socket缓冲 →(DMA)→ 网卡
                          ↑                              ↑
                    2次用户态/内核态切换          2次用户态/内核态切换
```

**零拷贝 = 减少拷贝 + 减少切换**（不是真的零拷贝）：
- **sendfile**（`FileChannel.transferTo`）：数据全程在内核空间，**不进用户空间**，2 次拷贝（DMA 到内核、内核到网卡）+ 2 次切换。Kafka 读消息用它。
- **mmap**：把文件映射到用户空间内存，操作内存等于操作文件，省一次 CPU 拷贝。Kafka 索引文件用它。

> 详见 `06-中间件/03-Kafka进阶.md` 1.7 节。

### 九、文件系统 ⭐⭐

#### 1. inode

- Linux 文件系统把文件分成 **inode**（索引节点）和 **数据块**。
- inode 存文件的**元数据**（大小、权限、所有者、指向数据块的指针），**不存文件名**。
- 文件名存在**目录**里（目录也是文件，内容是文件名 -> inode 号的映射）。

#### 2. 硬链接 vs 软链接

| | 硬链接 | 软链接（符号链接） |
|---|------|------|
| 本质 | 多个文件名指向**同一个 inode** | 一个独立文件，内容是指向目标**路径**的指针 |
| 删原文件 | 不影响（inode 引用计数-1，归零才删数据） | 失效（找不到目标） |
| 跨文件系统 | 不能 | 能 |
| 能否链接目录 | 一般不能 | 能 |

> 💡 删硬链接原文件数据还在，是因为 inode 有**引用计数**，多个硬链接共享一个 inode，计数归零才真正释放。软链接只是个"快捷方式"，指向路径，目标没了就悬空。

#### 3. VFS（虚拟文件系统）

Linux 用 VFS 给上层提供统一接口，屏蔽 ext4/xfs/proc 等不同文件系统的差异。"一切皆文件"就靠它。

### 十、其他高频小题 ⭐⭐⭐

#### 1. 僵尸进程与孤儿进程

- **僵尸进程 Zombie**：子进程**已退出**但父进程**没调 wait() 回收**其退出状态，子进程的 PCB 还留在系统占资源。危害：PCB 占用 PID，多了耗尽 PID。
- **孤儿进程 Orphan**：父进程先退出了，子进程被 **init（PID 1）** 收养，由 init 回收，**无危害**。
- **处理僵尸**：父进程调 wait/waitpid 回收；或杀掉不回收的父进程让 init 接管。

#### 2. 并发 vs 并行

- **并发**：同一时刻只有一个在执行，但多个任务**交替**进行（看起来同时）。单核也能并发。
- **并行**：同一时刻**多个任务真正同时**执行，需多核。

## 常见面试题

### Q1：进程和线程的区别？为什么线程切换比进程快？

进程是资源分配最小单位，有独立地址空间；线程是 CPU 调度最小单位，共享进程内存。线程切换在同一地址空间内，不用切换页表/地址空间（不刷 TLB），只切栈和寄存器，所以比进程快。（见核心概念一）

### Q2：进程间通信有哪些方式？哪个最快？

管道、消息队列、共享内存、信号量、信号、Socket。**共享内存最快**，因为数据直接读写同一块物理内存，不需要内核态-用户态拷贝；但需要配信号量同步。（见核心概念二）

### Q3：死锁的四个必要条件？怎么预防？

互斥、占有并等待、不可剥夺、循环等待。预防就破坏其中之一：资源有序分配破坏循环等待、一次性申请所有资源破坏占有并等待等。避免用银行家算法。（见核心概念四）

### Q4：select、poll、epoll 的区别？epoll 为什么快？（最高频）

select 有 1024 限制且每次全量拷贝 fd + 遍历全部 O(n)；poll 解除数量限制但仍遍历；epoll 用红黑树管理 fd、就绪链表只返回就绪的，增删用 epoll_ctl 不全量拷贝，wait 只取就绪的，性能高。epoll 快在：不全量拷贝、不全量遍历、回调机制把就绪 fd 加链表。（见核心概念七）

### Q5：epoll 的 LT 和 ET 模式有什么区别？

LT 水平触发，只要可读就一直通知，稳妥不易漏；ET 边缘触发，状态变化才通知一次，必须配合非阻塞 IO 一次读完，效率高但易丢事件。（见核心概念七）

### Q6：同步、异步、阻塞、非阻塞怎么区分？

阻塞/非阻塞是调用方要不要挂起等待；同步/异步是数据搬运谁干（应用自己搬=同步，内核搬好通知=异步）。可以两两组合，如同步非阻塞=轮询。AIO 才是真异步。（见核心概念七）

### Q7：常见的页面置换算法？LRU 怎么实现？

OPT（最优不可实现）、FIFO（有 Belady 异常）、LRU（最久未用，接近最优）、LFU、Clock。LRU 经典用哈希表+双向链表实现：访问移到头，淘汰删尾。（见核心概念五）

### Q8：虚拟内存是什么？有什么用？

每个进程有独立虚拟地址空间，由 OS+MMU 映射到物理内存。作用：进程隔离互不干扰、内存可超分配（swap 兜底）、简化编程（连续虚拟空间）。（见核心概念五）

### Q9：互斥锁和自旋锁的区别？分别什么时候用？

互斥锁拿不到就阻塞睡眠、让出 CPU，有切换开销，适合临界区长；自旋锁拿不到就忙等不让出 CPU，无切换开销但烧 CPU，适合临界区极短且很快能拿到。单核自旋锁可能死等。（见核心概念六）

### Q10：什么是零拷贝？传统 IO 有什么问题？

传统读文件发网络要 4 次拷贝 + 4 次上下文切换。零拷贝用 sendfile（数据不进用户空间，2 次拷贝 2 次切换）或 mmap（文件映射到内存省一次 CPU 拷贝）。Kafka 读消息用 sendfile，索引用 mmap。（见核心概念八）

### Q11：用户态和内核态是什么？什么时候切换？

内核态权限高能碰硬件，用户态受限保安全。系统调用（read/write/socket）、异常（缺页）、硬件中断时切到内核态。切换有保存上下文开销，频繁系统调用要优化。（见核心概念八）

### Q12：协程是什么？和线程比有什么优势？

协程是用户态轻量级线程，切换由程序控制不陷入内核，开销极小，一个线程能跑成万协程。代价是协作式调度，一个协程阻塞会卡住整个线程，所以协程里要用非阻塞 IO + 事件循环。Go 的 goroutine、Java 21 虚拟线程都是协程。（见核心概念一）

### Q13：僵尸进程和孤儿进程是什么？怎么处理？

僵尸进程是子进程已退出但父进程没 wait 回收，PCB 占资源；孤儿进程是父进程先退出，子进程被 init 收养无危害。处理僵尸：父进程调 wait/waitpid 回收，或杀掉父进程让 init 接管。（见核心概念十）

### Q14：硬链接和软链接的区别？

硬链接多个文件名指向同一 inode，删原文件不影响（引用计数）；软链接是独立文件指向目标路径，删原文件则悬空失效。硬链接不能跨文件系统、不能链目录；软链接可以。（见核心概念九）

## 资料勘误与重点提醒

> ⚠️ 操作系统资料/面经里流传的常见错误与必须澄清的点：

1. **"阻塞/非阻塞"和"同步/异步"是两个维度，别混为一谈**。阻塞非阻塞说调用方要不要等，同步异步说数据搬运谁干。正确组合：同步阻塞(BIO)、同步非阻塞(NIO轮询)、异步非阻塞(AIO)。**Linux 上真正的 AIO 支持有限**，io_uring 是较新的方案，成熟的真异步是 Windows IOCP。

2. **"epoll 用红黑树管理 fd"** 这个说法正确，但更要理解**就绪链表 + 回调**才是它快的核心。红黑树只是便于增删改 fd。

3. **select 的 1024 限制是 FD_SETSIZE 默认值**（可改但要重编内核/库），不是硬性的"系统限制"。poll 没有这个限制但仍要遍历。别把"select 限制 1024"和"poll 无限制"当成性能差异的全部--**核心差异是遍历 vs 不遍历**。

4. **ET 模式必须配非阻塞 IO**：ET 只通知一次，如果用阻塞 IO 读到没数据会卡死线程。这是 ET 编程最容易踩的坑，资料常漏。

5. **协程不是"没有开销"**：协程切换虽轻但仍有保存寄存器/栈的开销；且协程是协作式调度，**一个协程里写阻塞 IO 会卡死整个线程**，所以协程生态要求全程非阻塞 IO（这也是为什么 Go runtime 把阻塞调用都接管了）。

6. **自旋锁单核可能死锁**：单核下持有自旋锁的进程需要 CPU 才能释放锁，但被自旋者占着 CPU 死等，形成死锁。自旋锁只在**多核 + 临界区极短**时才有意义。

7. **"进程切换比线程慢"的根因是地址空间切换导致 TLB 刷新**，不只是"保存的东西多"。TLB 刷新后要重新查页表，访存开销才是大头。用 ASID（地址空间标识）可避免刷全 TLB。

8. **FIFO 的 Belady 异常**：页框数增加缺页率反而上升，这是 FIFO 特有的反直觉现象，LRU 和 OPT 不会有。这是个区分"记不记得住"的细节题。

9. **零拷贝不是"不拷贝"**：sendfile 仍有 2 次 DMA/CPU 拷贝，是"减少"拷贝和上下文切换。"零"指的是用户空间零参与。详见 Kafka 进阶勘误。

10. **重点补充（资料常漏的高频点）**：
    - **Reactor 三种模式**（单线程/多线程/主从），Netty 用主从 Reactor。
    - **共享内存配信号量**：共享内存没同步机制，必须自己加信号量/互斥锁。
    - **LRU 在 Redis 和 Java LinkedHashMap 的落地**：面试常追问"LRU 怎么实现"，哈希表+双向链表是标准答案。
    - **缺页中断**：访问的页不在内存触发缺页异常，陷入内核态把页从磁盘调入，这才是虚拟内存"按需换页"的核心。

> 📌 **本章总结**：操作系统面试就抓四块主线--**进程线程协程**（区别/切换开销/协程本质）、**同步互斥与死锁**（四条件/锁选型）、**内存管理**（虚拟内存/分页/TLB/页面置换 LRU）、**IO 模型**（四概念区分/select-poll-epoll/Reactor）。其中 **epoll 为什么快、IO 四概念区分、进程线程区别、LRU 实现**是四大必背点。零拷贝和用户态内核态把网络（Kafka/Nginx）和操作系统串成一条线，是 Java 后端的高频压轴。
