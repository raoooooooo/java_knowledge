# 25 - 经典场景实战

> 前面 24 章是零件，本章是成品。讲透 5 个企业高频场景怎么落地，外加 2 道系统设计题完整解答。面试「你做过什么场景」「设计一个 XX 系统」的弹药库。前 24 章的能力在这里组装。

## 一、场景一：企业知识库问答（最高频）★

### 1.1 业务诉求

- 企业内部文档（规章/产品手册/技术文档/FAQ）可自然语言问答，答案可溯源。

### 1.2 架构

```
[离线] 文档(PDF/Word/Confluence) -> 加载 -> 切分 -> Embedding -> 向量库
[在线] 用户问题 -> 查询改写 -> 混合检索 -> Rerank -> 拼 Prompt -> LLM 生成 + 引用溯源
[工程] 网关鉴权限流 | Trace/Token监控 | 评测集回归 | 安全审核
```

### 1.3 关键技术选型

| 环节 | 选型 | 理由 |
|------|------|------|
| 切分 | 递归/父子块 | 兼顾结构与上下文（05） |
| Embedding | BGE/通义 text-embedding-v3 | 中文强（05） |
| 向量库 | Milvus/Pgvector | 规模/已有栈（05） |
| 检索 | 混合检索+RRF | 语义+精确词（06） |
| Rerank | bge-reranker/gte-rerank | 精排（06） |
| LLM | qwen-plus/deepseek | 国内合规便宜（02） |
| 框架 | Spring AI + Alibaba | Java 生态（15/16） |

### 1.4 工程要点

- **引用溯源**：检索片段带来源/页码，Prompt 要求标注引用[1][2]（08 章）。
- **知识库更新**：增量更新（hash 判断变更）+ TTL（08 章）。
- **评测**：RAGAS 四指标 + 黄金集回归（08 章）。
- **安全**：PII 脱敏、Prompt 注入防护、内容审核（21 章）。

### 1.5 踩坑

- 切分切断表格/代码（改结构切分）。
- 专有名词召不回（加混合检索）。
- 检索空硬答幻觉（空结果拦截返回「无相关信息」）。
- 多语言混库检索差（分库或多语言 Embedding）。

## 二、场景二：智能客服 ★

### 2.1 业务诉求

- 用户咨询自动回答，复杂/高危转人工，多轮对话有记忆。

### 2.2 架构

```
用户消息 -> [意图识别] 
  |--FAQ/简单 --> RAG 知识库问答（场景一）
  |--需查业务 --> Agent+工具(查订单/物流/退款)
  |--复杂/高危 --> 转人工
[记忆] 按用户ID会话历史+长期偏好
[安全] 内容审核 + 敏感信息脱敏
```

### 2.3 关键设计

- **意图路由**：先判断意图（FAQ/业务查询/转人工），分流转不同处理。
- **Agent + 工具**：查订单/物流/退款等业务操作走 Function Calling（04/12 章）。
- **多轮记忆**：ChatMemory 存会话历史，长期记忆存用户偏好（11 章）。
- **人在环**：高危操作（退款/投诉）转人工确认（21 章）。
- **降级**：模型挂切备用、限流排队（22 章）。

### 2.4 踩坑

- 意图识别不准（路由分类器要训练/调优）。
- 工具调用越权（RBAC + 最小权限，21 章）。
- 多轮上下文爆（压缩/滑动窗口，10 章）。
- 用户数据泄露（PII 脱敏 + 多租户隔离）。
- 无人转人工兜底（设人工接管率指标）。

## 三、场景三：代码助手 / DevOps Agent

### 3.1 业务诉求

- 辅助开发：代码生成、Review、测试、排障。

### 3.2 架构

```
开发者请求 -> Agent(读代码/搜代码/跑命令/改代码)
  工具：Read/Write/Edit/Grep/Bash/子Agent
  记忆：项目规范(CLAUDE.md)
  安全：沙箱执行 + 危险操作确认
```

### 3.3 关键设计

- **工具集**：文件读写/搜索/命令执行/子 Agent 隔离（12 章）。
- **沙箱**：命令在容器内执行，限制文件/网络访问（21 章）。
- **自我修正**：代码改完跑测试，失败回灌让模型改（13 章）。
- **评测**：测试通过率/编译通过率（最客观，13 章）。
- **MCP 集成**：接 Git/Jira/CI 等工具（12 章）。

### 3.4 踩坑

- 命令执行越权（沙箱+确认）。
- 改错文件（权限范围限制）。
- 上下文爆（大代码库全读，子 Agent 隔离）。
- 没评测（测试通过率是最硬指标）。

## 四、场景四：数据分析 Agent（NL2SQL）★

### 4.1 业务诉求

- 用户自然语言提问 -> Agent 查数据库 -> 返回分析结果/图表。
- 「上个月销量 Top10 的商品」-> Agent 生成 SQL 查询 -> 返回结果。

### 4.2 架构

```
用户问题 -> [理解意图+选表] -> [生成SQL] -> [执行SQL] -> [结果分析+可视化]
  工具：查表结构/执行SQL/画图
  安全：只读SQL + 白名单表 + 行数限制
  评测：SQL正确率
```

### 4.3 关键设计

- **Schema 注入**：把库的表结构/字段说明/示例喂给模型，帮它生成正确 SQL。
- **NL2SQL 工具**：Function Calling 执行 SQL（04 章）。
- **安全**：只读权限（绝不给写/删）、白名单表（敏感表禁查）、行数限制、SQL 注入防护。
- **结果可视化**：执行结果让 LLM 解读 + 调画图工具生成图表。
- **Few-shot**：给「问题->SQL」示例提升准确率（03 章）。

### 4.4 踩坑

- SQL 生成错（Schema 要清晰、Few-shot 引导、复杂查询拆步）。
- 幻觉表名/字段（Schema 注入要准，别让模型瞎猜）。
- 越权（只读+白名单+行数限制）。
- SQL 注入（参数化/校验，别让模型生成恶意 SQL）。
- 大结果集（限制行数，别一次查百万行）。

## 五、场景五：工作流自动化

### 5.1 业务诉求

- 把多步骤业务流程自动化（审批/数据处理/报表生成）。

### 5.2 架构

```
[触发] -> [Graph编排] 节点1(LLM) -> 节点2(工具) -> 节点3(审核) -> 节点4(通知)
  人在环：关键节点暂停等人确认
  断点恢复：每步Checkpoint
```

### 5.3 关键设计

- **流程编排**：复杂流程用 Graph（条件/循环/并行，17 章）。
- **人在环**：关键步骤暂停确认（17 章）。
- **断点恢复**：Checkpointer 每步存状态（17 章）。
- **异步**：长流程异步走队列（19 章）。

## 六、系统设计题一：设计企业知识库问答系统 ★

> 经典面试题，完整解答框架。

**需求**：企业内部文档自然语言问答，答案可溯源，支持多用户，要上线。

**解答框架**：

1. **整体架构**：离线建库（切分/Embedding/入库）+ 在线检索生成 + 工程化（网关/可观测/安全/评测）。
2. **数据层**：向量库选 Milvus（大规模）或 Pgvector（已有 PG）；元数据（来源/页码/时间/分类）；关系库存业务数据。
3. **检索层**：查询改写+混合检索（Dense+Sparse+RRF）+Rerank 精排+元数据过滤+Top-K 调优（06 章）。
4. **生成层**：Prompt 强调只基于上下文、引用溯源、检索空返回「不知道」、降温度。
5. **工程化**：
   - 网关鉴权限流（19 章）。
   - 可观测 Trace/Token/质量（20 章）。
   - 安全 PII 脱敏+注入防护+审核（21 章）。
   - 模型路由降级（22 章）。
   - 评测 RAGAS+黄金集回归+灰度（23 章）。
   - 成本压缩+缓存（24 章）。
6. **容量与性能**：向量库按数据量/QPS 规划；缓存热门问答；流式输出。
7. **知识库更新**：增量更新（hash）+ TTL 清理（08 章）。
8. **取舍**：简单问答用普通 RAG，复杂多跳才上 Agentic RAG（07 章），别过度设计。

> 💡 **答系统设计题的关键**：不只讲技术栈，要讲**选型理由 + 工程化考量（容量/性能/安全/可观测/成本）+ 取舍**。体现架构思维。

## 七、系统设计题二：设计智能客服系统

**需求**：自动回答用户咨询，复杂转人工，多轮有记忆，要上线。

**解答框架**：

1. **整体架构**：意图路由（FAQ/业务查询/转人工）+ RAG 知识库 + Agent 工具 + 记忆 + 人工兜底。
2. **意图路由**：分类器/小模型判断意图，分流到不同处理。
3. **FAQ 路径**：RAG 知识库问答（场景一）。
4. **业务查询路径**：Agent + Function Calling 查订单/物流/退款（04/12 章）。
5. **记忆**：会话历史（ChatMemory）+ 长期偏好（向量记忆库，11 章）。
6. **人工兜底**：高危操作/复杂问题/低置信度转人工（人在环，21 章）。
7. **工程化**：网关限流（防成本失控）、多模型降级（主挂切备）、可观测（接管率指标）、安全（脱敏+审核+最小权限）、评测灰度。
8. **高可用**：运行时多副本无状态、状态外置、降级限流（19 章）。
9. **取舍**：简单 FAQ 用 RAG 够，业务操作才用 Agent，别所有都上 Agent。

## 八、常见面试题

1. **你做过什么 AI 场景？**
   （按实际讲，参考以上 5 个场景）。重点讲：业务诉求、架构、选型理由、踩坑、收益。

2. **设计一个企业知识库问答系统。**
   见第六节完整框架。要点：离线建库+在线检索生成+工程化（网关/可观测/安全/评测/成本）+引用溯源+增量更新。讲选型理由和取舍。

3. **NL2SQL 怎么做？有什么坑？**
   Schema 注入帮模型生成 SQL，Function Calling 执行，结果可视化。坑：SQL 生成错（Few-shot/拆步）、幻觉表名字段（Schema 准）、越权（只读+白名单+行数限制）、SQL 注入（校验）、大结果集（限行数）。

4. **智能客服怎么转人工？**
   意图路由判断复杂/高危转人工；低置信度转人工；高危操作（退款/投诉）人在环确认；监控人工接管率，过高说明自动化不够。

5. **企业知识库检索不准怎么优化？**
   查询改写+混合检索+Rerank+元数据过滤+Top-K 调优+上下文压缩（06 章）。先定位是检索还是生成问题（看 Trace），Bad Case 纳入评测集（08 章）。

6. **代码 Agent 怎么保证不改错文件？**
   权限范围限制（只能改指定目录）、沙箱执行、危险操作确认、改完跑测试验证（自我修正）、评测看测试通过率。

## 九、资料勘误与重点提醒

1. **「场景直接套框架」漏了工程化**：资料讲场景常只讲技术栈。实际要加网关/可观测/安全/评测/成本，才是上线系统，否则是 Demo。
2. **「所有场景都上 Agent」是过度设计**：资料常把 Agent 当万能。简单 FAQ/知识库问答用 RAG 够，业务操作才用 Agent，按场景选。
3. **NL2SQL 安全少强调**：资料讲 NL2SQL 常不强调只读+白名单+行数限制。这是高危场景（SQL 能查/改数据），安全是底线。
4. **系统设计题要讲取舍**：资料给标准答案不讲取舍。面试官要看架构思维：为什么这么选、什么场景不适用、成本考量。只堆技术栈不得高分。
5. **场景的评测常被忽略**：资料讲场景少讲评测。每个场景都要有评测指标（知识库 RAGAS、客服接管率、代码测试通过率），否则没法保证质量。
6. **人工兜底是场景必备**：资料讲自动化不提人工兜底。生产 Agent 必须有转人工机制（高危/复杂/低置信度），不能全自动裸跑。
