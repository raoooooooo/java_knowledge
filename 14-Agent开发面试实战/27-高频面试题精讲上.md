# 27 - 高频面试题精讲（上）

> 本章是面试突击弹药库：LLM/RAG/Prompt/Function Calling 四大类高频题，每题给「答案 + 话术 + 追问」。按这里背，面试能答得有体系。前 24 章是原理，本章是「怎么讲给面试官听」。

---

## 一、LLM 基础类

### Q1 大模型为什么会「幻觉」？怎么缓解？
**答**：根因是 LLM 生成「概率上像」的文本而非事实，它不区分真伪，只是在续写。缓解：① RAG 检索真实知识作为依据；② 工具调用获取可验证数据；③ 自我反思/校验；④ 降温度；⑤ 限定输出范围（只基于上下文）；⑥ Prompt 要求标注来源。
**话术**：幻觉是生成式模型本质决定的--它是在算条件概率续写，不是在查事实。所以缓解靠「给事实依据 + 校验 + 约束」，RAG 和工具调用是最有效的。
**追问**：长上下文能消除幻觉吗？答：不能完全，长上下文有 Lost in the Middle、注意力稀释，仍需 RAG 聚焦相关片段。

### Q2 预训练 / SFT / RLHF 分别解决什么？为什么顺序不能换？
**答**：预训练学语言和世界知识（基座）；SFT（监督微调）学按指令对话；RLHF（人类反馈强化学习）对齐人类偏好（安全有用）。顺序不能换：后一阶段依赖前一阶段能力--先有会说话的基座才能微调指令，先会指令才能做偏好对齐。
**话术**：三段式是「教说话->教听话->教懂事」。基座模型只会续写不会对话，SFT 后会对话但可能不当，RLHF 后才安全礼貌。
**追问**：DPO 是什么？答：Direct Preference Optimization，跳过奖励模型和 PPO 直接用偏好数据优化，更简单稳定，是主流（Llama3/Qwen/DeepSeek 采用）。

### Q3 temperature 和 top_p 区别？怎么选？
**答**：都是控制采样随机性，通常二选一。temperature 调整概率分布尖锐度（小=确定，大=随机），top_p 截断长尾低概率词（只从累计概率 p 的候选采样）。事实/代码/抽取设 temperature 低（0~0.3）求稳，创意设高。
**话术**：temperature 是「整体调尖锐度」，top_p 是「砍长尾」。OpenAI 官方建议二选一，不同时调。生产事实类我设 0~0.3，创意类 0.8~1.2。
**追问**：temperature=0 完全确定吗？答：不一定，受浮点/KV-cache 影响有微小差异，近似确定，设 seed 提高复现但不保证 100%。

### Q4 上下文窗口 1M 就够用了，为什么还要 RAG？
**答**：窗口大 ≠ 能用好。长上下文有：① Lost in the Middle（中间内容被忽略）；② 注意力稀释；③ 成本高（全塞 token 贵）；④ 速度慢；⑤ 知识更新难（改了要重塞）。RAG 只检索相关片段，更准更省更快，知识可随时更新。
**话术**：长上下文适合「一次读全」单份长文档，不适合海量知识库检索。两者配合：RAG 检索 + 长上下文容纳检索结果。
**追问**：Lost in the Middle 怎么缓解？答：重要信息放头/尾、用 RAG 聚焦相关片段减少输入、关键信息锚定。

### Q5 Token 怎么算？输入输出都算钱吗？
**答**：都算，输入输出分别计费，输出通常贵 3~5 倍。中文 1 字 ≈ 1~2 token，英文 1 词 ≈ 1.3 token。API 返回 usage 字段是计费依据。多轮对话历史也是输入 token，越长越贵。
**话术**：成本控制三板斧--压缩上下文（减输入）、用小模型（降单价）、缓存（复用结果）。监控按用户/Agent 统计 token 发现异常。

## 二、RAG 类 ★ 最高频

### Q6 RAG 的完整流程是什么？
**答**：离线建库（加载->切分->Embedding->存向量库）+ 在线检索（Query Embedding->检索 Top-K->Rerank）+ 生成（拼 Prompt->LLM）。瓶颈往往在检索而非生成。
**话术**：RAG 三阶段我讲清楚离线建库、在线检索、生成，重点强调瓶颈在检索，所以切分和检索优化是关键。
**追问**：RAG 和微调怎么选？答：知识频繁变/需溯源/数据量大选 RAG；改风格/格式/领域术语习惯/有稳定指令对选微调；常组合。

### Q7 RAG 检索不准怎么优化？★ 必考
**答**：多层优化框架：① 查询改写（HyDE/扩展/分解）；② 元数据过滤缩小范围；③ 混合检索（Dense+Sparse+RRF）；④ Rerank（Cross-Encoder）精排；⑤ Top-K 调优（召回大、精排小）；⑥ 上下文压缩（LLMLingua）。
**话术**：这是标准框架，我会先看 Trace 定位是检索还是生成问题，再针对性优化。Bad Case 纳入评测集防回归。
**追问**：为什么需要 Rerank？答：向量检索是 Bi-Encoder 快但粗（可预计算召回），Rerank 是 Cross-Encoder Query+Doc 拼一起精排准但慢，两阶段粗筛+精排。

### Q8 文档怎么切分？
**答**：策略有固定长度（+重叠）、按语义边界（段落/标题）、递归切分（兼顾结构，推荐）、语义切分（按相似度变化点）、父子块（小块检索大块返回，生产推荐）。经验 chunk 500~1000 token，overlap 10%~20%。
**话术**：切分质量决定检索上限。我会用递归切分或父子块，加元数据（来源/页码）便于过滤和溯源。代码/表格要结构感知切分。
**追问**：切分把语义切断了怎么办？答：用语义/递归/父子块切分、加重叠、父子块（小块检索准返回所属大块保证上下文）。

### Q9 向量数据库怎么选？
**答**：看规模和场景。中小+已有 PG 用 Pgvector；大规模+私有化用 Milvus；已用 ES+要混合检索用 ES；强元数据过滤用 Qdrant；低延迟+缓存用 Redis；原型用 Chroma。Spring AI VectorStore 抽象可一套代码切库。
**追问**：HNSW 和 IVF 怎么选？答：HNSW 基于图速度快精度高但吃内存（主流）；IVF+PQ 聚簇量化省内存适合超大规模（牺牲少量精度）。

### Q10 RAGAS 四个指标分别衡量什么？
**答**：Context Precision/Recall 衡量检索阶段（检索得准不准、全不全），Faithfulness/Answer Relevancy 衡量生成阶段（答得忠不忠、切不切题）。瓶颈常在检索。
**话术**：RAG 评测分两阶段，检索看 Context 指标，生成看 Faithfulness/Relevancy。用 LLM-as-Judge 自动打分 + 黄金集回归。
**追问**：Bad Case 怎么分析？答：看 Trace 判断检索还是生成问题，检索没召回改切分/Embedding/Query，召回了答错改 Prompt/模型，Bad Case 纳入评测集防回归。

### Q11 GraphRAG 解决了什么传统 RAG 解决不了的问题？
**答**：全局/总结性问题。传统 RAG 只捞局部片段答不了「这批文档整体讲什么」「A 和 B 什么关系」；GraphRAG 抽实体关系建知识图谱+社区摘要，全局问题用摘要答。代价是建图贵。
**追问**：Agentic RAG 是什么？答：RAG+Agent，模型自主决定查什么、查几次、换不换库，多跳检索+反思。复杂多跳才用，简单问答普通 RAG 够，别过度设计。

## 三、Prompt 类

### Q12 怎么写好一个 Prompt？
**答**：工程化三要素：结构化（角色/任务/格式/约束/示例）、指令数据分离（XML 标签）、Few-shot 引导。配合结构化输出（JSON Mode/Schema）保证可解析。Prompt 当代码管理：模板化、版本化、评测回归。
**话术**：我会把 Prompt 当代码--模板分离变量、配置中心管理版本、改动走 review + 黄金集回归，不凭感觉改。
**追问**：Few-shot 怎么选示例？答：2~5 个有代表性的，覆盖各类情况（正负面都要），质量 > 数量，示例偏差会过拟合。

### Q13 CoT 是什么？什么时候用？
**答**：让模型把推理过程写出来再给答案。有效因为每步生成 token 成为下一步上下文，等价扩展计算图。适用数学/逻辑推理；简单分类抽取别用，慢且可能引错。
**追问**：ReAct 和 CoT 区别？答：CoT 只推理不调工具；ReAct 推理+行动（调工具）交替，是 Agent 基石。

### Q14 Prompt 注入是什么？怎么防？
**答**：用户输入藏指令劫持模型（类似 SQL 注入但自然语言无法完全转义）。多层防御：指令数据隔离（XML 标签）、输入输出审核、指令强化、结构化约束，核心是最小权限--即使被注入也限制危害。无银弹。
**话术**：Prompt 注入没有 100% 解决方案，自然语言无法像 SQL 参数化完全转义。所以核心是最小权限--即使被注入，Agent 也干不了太坏的事（危险操作要确认、工具权限最小、数据脱敏）。
**追问**：system prompt 能放用户输入吗？答：绝不能。用户输入进 user，system 只放固定指令。用户能改 system 就劫持了。

### Q15 怎么让模型稳定输出 JSON？
**答**：三层：Prompt 约束（只输出 JSON + Few-shot）-> JSON Mode（合法 JSON）-> Structured Output（给 Schema 严格匹配）。Spring AI 用 entity(Class) 自动转 Java 对象最稳。仍要 Schema 校验兜底 + 解析失败重试。
**追问**：JSON Mode 保证输出正确吗？答：只保证「是合法 JSON」，不保证「字段对/值对」。要 Schema 校验，Structured Output（给 Schema）才更可靠。

## 四、Function Calling / Tool 类 ★

### Q16 Function Calling 的流程是什么？
**答**：开发者定义工具（名/描述/参数 Schema）-> 随请求发给模型 -> 模型决定是否调，要调则输出「函数名+参数」-> 框架执行真实函数 -> 结果作为 tool 消息回灌上下文 -> 模型基于结果继续推理或给最终答案。模型不执行工具，框架执行。
**话术**：模型是大脑只说调什么，框架是手脚真正执行。结果回灌是循环引擎，这就是 Agent Loop 的雏形。
**追问**：模型不调工具怎么办？答：检查 description 是否清晰、参数是否太复杂、模型是否支持 FC（小模型可能不支持）。

### Q17 Function Calling 和 MCP 什么关系？冲突吗？★ 必考
**答**：不冲突，是模型层和协议层关系。Function Calling 是模型能力（输出结构化调用），MCP 是协议标准（工具发现/调用/通信标准化）。MCP Server 暴露的工具最终靠 Function Calling 让模型调。MCP 把 M×N 集成变 M+N。
**话术**：MCP 是协议层解决「工具怎么被发现、怎么通信标准化」，Function Calling 是模型层解决「模型怎么输出调用」。完整链路：模型 --(FC)--> Host --(MCP)--> Server --> 真实工具。
**追问**：为什么要 MCP？答：M×N 问题。没 MCP 每个框架×每个工具要写 M×N 份集成；有 MCP 框架实现 Client、工具实现 Server，变 M+N 即插即用。

### Q18 工具失败怎么处理？
**答**：catch 异常返回可读错误（含怎么改的提示），让模型据错误修正参数重试。设重试次数上限。不是简单重试也不是崩循环。写操作要幂等防重复执行。
**话术**：Agent 错误处理和传统不同--把错误信息回灌让模型自我修正。工具返回「订单号格式错应为 ORD 开头」，模型下次会改格式。这是 Agent 自我修正的基础。
**追问**：工具太多选错怎么办？答：分组/按需加载（Skill）/路由分流/限制单次 10~20 个。工具过多注意力稀释。

### Q19 工具设计有哪些原则？
**答**：三原则：描述即接口（说清做什么/何时用/返回什么）、参数要简单（少+枚举约束+默认值）、错误要可读（返回可读错误让模型修正重试，不是 null/异常崩循环）。
**追问**：危险工具怎么处理？答：人在环确认（下单/退款/删数据/外发必须人工确认），不能让模型自主执行。写操作幂等。

### Q20 Structured Output 和 Function Calling 什么关系？
**答**：Structured Output 让模型输出结构化数据（不执行），Function Calling 是调工具（框架执行）。联系：FC 的参数传递用 Structured Output 保证格式。Spring AI 的 entity(Class) 是 Structured Output，@Tool 是 Function Calling。

## 五、面试话术总结

### 答题原则

1. **先结论后展开**：一句话核心答案，再展开细节。
2. **带原理**：不只说怎么做，说为什么（体现深度）。
3. **带取舍**：讲适用场景和不适用场景（体现架构思维）。
4. **带项目**：能关联「我们项目里这么做」更可信。
5. **诚实**：不懂别说懂，说「我了解的是...没深入实践」比硬编好。

### 高频话术模板

- **RAG 类**：「瓶颈在检索，所以我会先看 Trace 定位是检索还是生成问题，再针对性优化...Bad Case 纳入评测集防回归。」
- **Agent 类**：「工具调用是循环引擎，模型决定下一步是 Agent 自主性来源...设最大步数防死循环。」
- **工程化类**：「这是分布式系统老套路迁移--无状态运行时+状态外置+网关+限流降级，AI 特有的是 token 成本和非确定性要加可观测和评测。」
- **选型类**：「看场景：国内 Spring Boot 项目优先 Spring AI + Alibaba + 通义；简单任务别过度设计。」

## 六、资料勘误与重点提醒

1. **面试题别死记答案**：资料给的标准答案要理解原理，面试官会追问。背答案一追问露馅，懂原理能举一反三。
2. **「我会」和「我做过」区别**：面试官爱问「你项目里怎么做的」。没做过要能讲合理方案+踩坑，别硬编「做过」被追问穿帮。
3. **答案要带取舍**：资料常给唯一答案。实际面试要看场景，讲「什么情况用 A 什么情况用 B」更体现深度。
4. **追问才是考点**：资料常只给主问题答案。面试官追问（为什么/怎么办/有什么坑）才是区分度，准备时要预想追问。
5. **别贬低传统方法**：答 AI 方案别说「传统方法不行」。要说「传统方法适合 X，AI 适合 Y，看场景」，体现客观。
6. **诚实比硬编好**：不懂说「这块我了解概念没深入实践，我的理解是...」，比硬编被穿帮好。面试官更看重诚实和学习能力。
