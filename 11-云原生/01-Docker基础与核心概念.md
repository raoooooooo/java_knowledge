# Docker 基础与核心概念

## 一、核心概念

### 1.1 Docker 概述

**什么是 Docker？**
- Docker 是一个开源的容器化平台
- 用于自动化部署、扩展和管理应用程序
- 将应用及其依赖打包到轻量级、可移植的容器中
- 容器在任何环境中都能一致运行

**Docker 的核心优势**
- 快速部署：秒级启动，开箱即用
- 环境一致性：开发/测试/生产环境完全一致
- 轻量级：共享主机内核，资源占用小
- 可移植性：一次构建，到处运行
- 版本控制：镜像分层存储，支持版本管理
- 隔离性：容器间资源隔离，互不影响

### 1.2 容器 vs 虚拟机

| 特性 | 容器（Docker） | 虚拟机（VM） |
|------|---------------|-------------|
| 虚拟化层级 | 操作系统级 | 硬件级 |
| 内核 | 共享宿主机内核 | 独立 Guest OS 内核 |
| 启动速度 | 秒级 | 分钟级 |
| 资源占用 | MB 级 | GB 级 |
| 性能损耗 | 几乎无损耗 | 约 5-20% |
| 隔离性 | 进程级隔离 | 完全隔离 |
| 镜像大小 | 几十 MB | 几 GB |

### 1.3 Docker 三大核心概念

#### 镜像（Image）
- 容器的只读模板，包含应用运行所需的所有内容
- 采用分层存储机制（Union FS）
- 每层都是只读的，通过层叠构建完整镜像
- 镜像可以基于基础镜像构建新镜像
- 镜像不可变，修改只能通过新建层实现

#### 容器（Container）
- 镜像的运行实例，可读写
- 容器 = 镜像 + 读写层
- 每个容器相互隔离，有自己的文件系统、网络、进程空间
- 容器生命周期：创建 → 启动 → 暂停 → 停止 → 删除
- 容器删除后，读写层数据丢失，需通过 Volume 持久化

#### 仓库（Repository）
- 集中存储镜像的地方
- Docker Hub 是官方公共仓库
- 分为公共仓库和私有仓库
- 支持镜像的上传、下载、版本管理

### 1.4 Docker 架构

**Client-Server 架构**
```
Docker Client (CLI/API) → Docker Daemon → Container Runtime (runc)
                                              ↓
                                          Linux Kernel
                                          (Namespaces + Cgroups)
```

**主要组件：**
1. **Docker Client**：用户交互界面，发送命令
2. **Docker Daemon**：后台服务，管理镜像、容器、网络、存储
3. **Containerd**：工业级容器运行时，管理容器生命周期
4. **runc**：轻量级运行时工具，根据 OCI 规范创建和运行容器

### 1.5 Docker 底层技术

#### Namespaces（命名空间）
提供系统资源隔离：
- **PID**：进程隔离
- **NET**：网络栈隔离
- **MNT**：文件系统挂载点隔离
- **UTS**：主机名和域名隔离
- **IPC**：进程间通信隔离
- **USER**：用户和用户组隔离

#### Cgroups（控制组）
限制和审计资源使用：
- **CPU**：CPU 使用限制
- **Memory**：内存使用限制
- **Block IO**：块设备 IO 限制
- **Network**：网络带宽限制
- Devices：设备访问控制

#### Union FS（联合文件系统）
- 支持将多个目录挂载到同一个虚拟文件系统
- 实现镜像分层存储和写时复制（CoW）
- 常见实现：AUFS、OverlayFS、Device Mapper

### 1.6 写时复制（Copy-on-Write）

**工作原理：**
- 所有镜像层都是只读的
- 容器启动时，在镜像层顶部添加读写层
- 读取文件：从上层向下查找，找到即读取
- 修改文件：将文件从只读层复制到读写层，然后修改
- 删除文件：在读写层创建「whiteout」文件标记删除

**优点：**
- 节省磁盘空间：多个容器共享镜像层
- 快速启动：无需复制整个文件系统
- 易于管理：分层存储便于版本控制

## 二、常见面试题

### Q1：Docker 容器和虚拟机有什么区别？

**核心回答：**
> Docker 是操作系统级虚拟化，共享宿主机内核，秒级启动，资源占用小（MB 级），性能损耗低；虚拟机是硬件级虚拟化，运行完整 Guest OS，分钟级启动，资源占用大（GB 级），性能损耗约 5-20%。容器适合微服务部署，虚拟机适合强隔离的多租户场景。

**追问可能：**
- 容器的隔离性是否足够？
- 什么场景下应该选择虚拟机而不是容器？

### Q2：Docker 镜像和容器的关系是什么？

**核心回答：**
> 镜像（Image）是容器的只读模板，包含应用和依赖；容器（Container）是镜像的运行实例。类比：镜像类似类（Class），容器类似对象实例（Object）。容器 = 镜像 + 可读写层，容器删除后数据会丢失，持久化需要 Volume。

**追问可能：**
- 镜像分层的原理是什么？
- 如何将容器保存为镜像？

### Q3：什么是写时复制（Copy-on-Write）？

**核心回答：**
> Docker 采用写时复制机制，所有镜像层都是只读的，容器启动时在顶部添加读写层。读取文件时从上层向下查找，修改文件时才将文件从只读层复制到读写层进行修改。这样大大节省了磁盘空间，实现了快速启动和镜像共享。

**追问可能：**
- 写时复制有什么缺点？
- 哪些文件系统支持写时复制？

### Q4：Docker 容器的隔离是如何实现的？

**核心回答：**
> Docker 通过 Linux Namespaces 实现资源隔离，通过 Cgroups 实现资源限制。Namespaces 提供 PID、NET、MNT、UTS、IPC、USER 六个维度的隔离，让容器感觉自己是独立的系统；Cgroups 限制容器的 CPU、内存、IO 等资源使用，防止容器间互相影响。

**追问可能：**
- Namespace 和 Cgroup 是 Linux 内核特性吗？
- Docker 隔离和 K8s 有什么关系？

### Q5：Docker 的底层架构是怎样的？

**核心回答：**
> Docker 采用 Client-Server 架构：Client（CLI）发送命令给 Daemon，Daemon 调用 Containerd 管理容器生命周期，Containerd 再调用 runc 根据 OCI 规范创建和运行容器。底层依赖 Linux 内核的 Namespaces 和 Cgroups 技术。

**追问可能：**
- Containerd 和 runc 的作用分别是什么？
- Docker Daemon 是单进程吗？有什么问题？

### Q6：为什么 Docker 启动比虚拟机快？

**核心回答：**
> 1. **无需启动完整 OS**：容器共享宿主机内核，不需要引导 Guest OS；
> 2. **写时复制机制**：无需复制整个文件系统，秒级创建；
> 3. **资源轻量**：容器是进程级隔离，启动开销极小；
> 4. **镜像缓存**：分层镜像可复用已下载的层。

### Q7：Docker 镜像分层有什么优势和缺点？

**优势：**
1. **节省存储空间**：多层共享，复用率高
2. **快速分发**：只拉取变化的层
3. **易于版本管理**：每层对应一个变更
4. **支持继承**：基于基础镜像构建新镜像

**缺点：**
1. **层数过多影响性能**：文件查找需要遍历多层
2. **写时复制开销**：第一次修改文件需要复制
3. **层数限制**：AUFS 曾限制 127 层（现在已放宽）

### Q8：什么是 Docker Volume？为什么需要它？

**核心回答：**
> Volume 是 Docker 持久化数据的机制。容器的文件系统是临时的，容器删除后数据会丢失，Volume 可以将容器内的数据目录映射到宿主机或外部存储，实现数据持久化和容器间数据共享。Volume 不受容器生命周期影响，支持多种驱动（local、nfs、cloud 存储等）。

**追问可能：**
- Volume 和 Bind Mount 的区别？
- 如何备份和恢复 Volume 数据？

### Q9：如何优化 Docker 镜像大小？

**优化方法：**
1. **使用 Alpine 基础镜像**（比 Ubuntu 小很多）
2. **多阶段构建（Multi-stage build）**：构建环境和运行环境分离
3. **合并 RUN 指令**：减少镜像层数
4. **清理缓存**：安装包后清理 apt/yum 缓存
5. **使用 .dockerignore**：排除不必要的文件
6. **压缩镜像层**：使用 docker-squash 等工具

### Q10：Docker 容器之间如何通信？

**通信方式：**
1. **Link 方式（已过时）**：通过容器名连接，单向通信
2. **Bridge 网络**：同一桥接网络下的容器通过 IP 或容器名互访
3. **Host 网络**：共享宿主机网络栈，性能最好但隔离性差
4. **Overlay 网络**：跨主机容器通信，用于 Swarm/K8s 集群
5. **发布端口**：通过宿主机端口映射对外提供服务
