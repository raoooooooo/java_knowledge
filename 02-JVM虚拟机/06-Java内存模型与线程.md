# Java内存模型与线程

> 📌 **一句话理解**：为了让Java程序在各种CPU和操作系统下都能有一致的内存访问效果，JVM定义了一套规则，这套规则就是**Java内存模型（JMM）**。

---

## 核心概念

### 一、为什么需要Java内存模型？

**先看一个你天天遇到但不知道为什么的问题：**

```java
public class Test {
    private static boolean flag = true;
    
    public static void main(String[] args) throws InterruptedException {
        new Thread(() -> {
            while (flag) {
                // 空循环
            }
            System.out.println("循环结束！");
        }).start();
        
        Thread.sleep(1000);
        flag = false;  // 主线程把flag改成false
        System.out.println("flag已经改成false了！");
    }
}
```

**你觉得会输出"循环结束"吗？**

> 🔴 **答案：在某些JVM和某些优化级别下，永远不会输出！**

**为什么？**
因为子线程看到的`flag`可能一直是`true`，即使主线程已经改成`false`了！

这就是**内存可见性问题**。不同的CPU、不同的操作系统，内存模型不一样，同样的代码在不同机器上执行结果可能不同。Java为了"一次编写，到处运行"，必须定义一套统一的规则，让所有平台都遵守——这就是**Java内存模型（JMM）**。

---

### 二、Java内存模型的基础结构 ⭐⭐⭐

#### 1. 主内存 vs 工作内存

JMM规定了：
- **主内存（Main Memory）**：所有线程共享的区域，所有变量都存在主内存里
- **工作内存（Working Memory）**：每个线程自己私有的区域，保存了该线程用到的变量的**副本拷贝**

**类比理解：**
- 主内存 = 仓库
- 工作内存 = 每个工人自己的工作台
- 线程 = 工人

工人要操作某个零件（变量）：
1. 先从仓库把零件拿到自己的工作台上
2. 在工作台上加工
3. 加工完了再放回仓库

**重要规则：**
> ✅ 线程不能直接操作主内存的变量，只能操作自己工作内存里的副本
> ✅ 线程之间也不能互相访问对方的工作内存
> ✅ 变量值的传递必须通过主内存来完成

**结构图：**

```
                    ┌──────────────────────────────────┐
                    │          主内存（共享）            │
                    │  变量A  变量B  变量C  变量D       │
                    └───┬──────────┬───────────┬───────┘
                        │          │           │
         拷贝到工作内存 │          │           │
                        ▼          ▼           ▼
              ┌───────────┐ ┌───────────┐ ┌───────────┐
              │ 线程1工作  │ │ 线程2工作  │ │ 线程3工作  │
              │ 内存（私有）│ │ 内存（私有）│ │ 内存（私有）│
              │ 变量A副本  │ │ 变量B副本  │ │ 变量C副本  │
              └───────────┘ └───────────┘ └───────────┘
```

**回到开头的例子，为什么循环不会结束？**
```
时间线：
1. 子线程从主内存读取 flag=true 到自己的工作内存
2. 子线程一直在用自己工作内存里的 flag=true 循环
3. 主线程把 flag=false 写回主内存
4. 但是！子线程不知道主内存的flag变了，还是用自己工作内存里的旧值
5. → 死循环！
```

---

#### 2. 内存间交互操作（8种原子操作）

JMM定义了8种原子操作来完成"主内存 ↔ 工作内存"的交互：

| 操作 | 作用对象 | 说明 |
|------|---------|------|
| **lock** | 主内存变量 | 把变量"锁定"，告诉其他线程这变量我占了 |
| **unlock** | 主内存变量 | 把变量"解锁"，释放后其他线程可以用了 |
| **read** | 主内存变量 | 把变量值从主内存读出来，准备传输 |
| **load** | 工作内存变量 | 把read出来的值放到工作内存的变量副本里 |
| **use** | 工作内存变量 | 把工作内存的值传给执行引擎（用来计算） |
| **assign** | 工作内存变量 | 执行引擎把计算结果赋值回工作内存 |
| **store** | 工作内存变量 | 把工作内存的值传出去，准备写回主内存 |
| **write** | 主内存变量 | 把store出来的值写到主内存的变量里 |

**完整流程示例：** 线程把变量`a`从1改成2

```
1. read   ：主内存 a=1 → 读出来，准备传输
2. load   ：放到工作内存 a=1
3. use    ：交给执行引擎计算
4. assign ：计算结果a=2，赋值回工作内存
5. store  ：工作内存 a=2 → 传出去，准备写回
6. write  ：写回主内存 a=2
```

**重要规则（理解就行，不用死记）：**
- read和load必须成对出现（要读就必须完整读进来）
- store和write必须成对出现（要写就必须完整写回去）
- 变量加了lock之后，就会清空工作内存中这个变量的值，需要重新read/load
- 变量unlock之前，必须先把值同步回主内存（store+write）

### 三、JMM的三大特性 ⭐⭐⭐

这是面试必背！JMM主要就是围绕这三个特性建立的。

#### 1. 原子性（Atomicity）

**概念：** 一个操作要么全部执行完，要么完全不执行，中间不能被打断。

**哪些是原子操作？**
- 基本类型的读写（除了long和double的非volatile读写）
- synchronized块内的操作
- lock和unlock操作

**举个例子：**
```java
int a = 10;      // 原子操作，直接赋值
a++;             // 不是原子操作！是"读-改-写"三步
```

`a++`为什么不是原子的？
```
1. 读取a的原值   → use
2. 加1           → 计算
3. 写回新值       → assign
```
这三步中间任何一步都可能被其他线程打断。

---

#### 2. 可见性（Visibility）⭐

**概念：** 当一个线程修改了共享变量的值，其他线程能够**立即看到**这个修改。

**怎么保证可见性？** Java提供了三种方式：

| 方式 | 原理 |
|------|------|
| **volatile** | 修改后立即写回主内存，读取前先从主内存刷新最新值 |
| **synchronized** | unlock前必须把变量写回主内存 |
| **final** | final字段在构造方法中初始化完成后，其他线程就能看到（而且不会变） |

**回到开头的例子怎么解决？**
很简单，给flag加上`volatile`就行：
```java
private volatile static boolean flag = true;
```

这样主线程修改flag后，会立即写回主内存，并且让其他线程工作内存里的flag副本失效，子线程下次读flag时就必须重新从主内存读最新的。

---

#### 3. 有序性（Ordering）⭐

**概念：** 程序执行的顺序按照代码的先后顺序执行？**不一定！**

因为编译器和CPU为了性能，会对指令进行**重排序**。只要不影响单线程的执行结果，顺序可以随便改。

**举个例子：**
```java
int a = 1;      // 语句1
int b = 2;      // 语句2
a = a + 3;      // 语句3
```

语句1和语句2谁先执行不影响结果，所以CPU可能会把顺序改成：语句2 → 语句1 → 语句3，或者语句1 → 语句3 → 语句2。

**单线程没问题，但多线程就出问题了！**

经典的"懒加载单例"问题：
```java
class Singleton {
    private static Singleton instance;
    
    public static Singleton getInstance() {
        if (instance == null) {          // 第一次检查
            synchronized (Singleton.class) {
                if (instance == null) {  // 第二次检查
                    instance = new Singleton();  // 问题在这里！
                }
            }
        }
        return instance;
    }
}
```

**`new Singleton()` 不是原子的！** 它可以拆成三步：
```
1. 分配对象内存空间
2. 初始化对象（调用构造方法）
3. 把instance指向分配的内存地址
```

如果发生重排序，顺序可能变成：
```
1. 分配对象内存空间
3. 把instance指向分配的内存地址  ← 先执行了！
2. 初始化对象                   ← 还没执行！
```

这时候另一个线程进来检查`instance == null`，发现instance已经不为null了，直接返回，但这个对象**还没初始化**！用的时候就会出问题。

**怎么禁止重排序？** 用`volatile`！

所以正确的双重检查锁单例写法是：
```java
private volatile static Singleton instance;  // 必须加volatile！
```

> 💡 面试常考：volatile两大作用：1. 保证可见性；2. 禁止指令重排序！

### 四、volatile关键字详解 ⭐⭐⭐

这是面试必问！

#### volatile的两个特性：

| 特性 | 说明 |
|------|------|
| **可见性** | 对volatile变量的写，立即对其他线程可见 |
| **禁止重排序** | volatile变量前后的指令不能随便重排 |

#### volatile的实现原理（面试加分项）：

volatile变量写操作的汇编代码会加一个**`lock`前缀**，这个lock前缀会做两件事：
1. **立即写回主内存**：把当前处理器缓存行的数据立即写回系统内存
2. **使其他缓存失效**：写回主内存的操作会让其他CPU里缓存了这个内存地址的数据失效（MESI协议）

#### volatile能保证原子性吗？

**答案：不能！**

比如`volatile int a; a++`，还是不保证原子性，因为a++是"读-改-写"三步，volatile只能保证读的时候是最新的，但写的时候可能已经被其他线程改过了。

**什么时候用volatile？**
1. 状态标志（比如开头的flag例子）
2. 双重检查锁的单例模式
3. 不需要原子性的计数器（如果只有一个线程写，可以用）

### 五、先行发生原则（Happens-Before）⭐⭐⭐

这是JMM的核心！不要死记概念，理解它的作用。

**概念：** 如果操作A **先行发生于** 操作B，那么操作A的影响（修改了哪些变量、发了哪些消息等）**一定能被操作B看到**。

**为什么需要它？**
判断多线程环境下，什么时候一个线程的修改对另一个线程是可见的，**不需要猜，不需要加锁，看有没有符合happens-before规则就行**。

#### 8条Happens-Before规则（记住常用的5条就行）

| 规则 | 说明 | 举例 |
|------|------|------|
| **1. 程序次序规则** | 同一个线程内，写在前面的操作先行发生于写在后面的操作 | 同一个线程里，先执行a=1，再执行b=a，那a=1的结果对b=a可见 |
| **2. 管程锁定规则** | unlock操作先行发生于后面对同一个锁的lock操作 | 线程A把锁释放了，线程B拿到这个锁，A的修改对B可见 |
| **3. volatile变量规则** | 对volatile变量的写操作先行发生于后面对这个变量的读操作 | 线程A写了volatile变量v，线程B读v，A的修改对B可见 |
| **4. 线程启动规则** | Thread.start()方法先行发生于此线程的每一个动作 | 主线程调用thread.start()后，thread线程能看到主线程在start前的所有修改 |
| **5. 线程终止规则** | 线程的所有操作都先行发生于对此线程的终止检测 | 线程执行完了，主线程join()返回后，能看到线程的所有修改 |
| **6. 线程中断规则** | interrupt()调用先行发生于被中断线程检测到中断事件 |  |
| **7. 对象终结规则** | 对象的初始化完成先行发生于finalize()方法 |  |
| **8. 传递性** | A先行于B，B先行于C → A先行于C |  |

**举个例子说明怎么用：**

```java
private int value = 0;
private volatile boolean flag = false;

// 线程A
public void writer() {
    value = 123;        // 操作1
    flag = true;        // 操作2 （volatile写）
}

// 线程B
public void reader() {
    if (flag) {          // 操作3 （volatile读）
        int a = value;   // 操作4
    }
}
```

**问：线程B看到的a一定是123吗？**

**用happens-before推导：**
- 操作1 happens-before 操作2 （程序次序规则：同一个线程内）
- 操作2 happens-before 操作3 （volatile变量规则：写先行于读）
- 操作3 happens-before 操作4 （程序次序规则：同一个线程内）
- 操作1 happens-before 操作4 （传递性）

**结论：a一定等于123！**

> 💡 **神奇吧？** value不是volatile也没关系！只要flag是volatile，就能通过volatile规则+传递性保证value的可见性！

### 六、Java线程的实现

#### 1. 线程是什么？

**一句话：** 线程是CPU调度的最小单位，进程是资源分配的最小单位。

一个进程里可以有多个线程，这些线程共享进程的资源（内存、文件句柄等），但每个线程有自己的程序计数器、虚拟机栈、本地方法栈。

#### 2. 线程的三种实现方式

| 实现方式 | 说明 | 优点 | 缺点 |
|---------|------|------|------|
| **1. 内核线程实现** | 由操作系统内核来管理线程，线程的切换由内核完成 | 线程阻塞了不会影响其他线程 | 切换成本高，需要从用户态切到内核态 |
| **2. 用户线程实现** | 完全在用户空间实现，内核感知不到 | 切换快，不需要内核参与 | 一个线程阻塞，整个进程都阻塞；很难利用多核CPU |
| **3. 混合实现** | 内核线程+用户线程的混合，N个用户线程映射到M个内核线程 | 结合两者优点 | 实现复杂 |

**Java线程是怎么实现的？**
- JDK 1.2之前：绿色线程（用户线程实现）
- **JDK 1.3及之后：每个Java线程直接映射到操作系统的原生线程（内核线程实现）**

所以你调用`Thread.start()`，实际上是调用操作系统的原生线程API来创建线程。

### 七、Java线程的状态转换 ⭐⭐⭐

#### 1. 线程的6种状态

| 状态 | 说明 |
|------|------|
| **NEW** | 新建，线程对象创建了，但还没调用start() |
| **RUNNABLE** | 可运行，已经调用了start()，等待CPU调度或者正在运行 |
| **BLOCKED** | 阻塞，等着拿锁（synchronized） |
| **WAITING** | 无限期等待，等着其他线程唤醒（wait()、join()、LockSupport.park()） |
| **TIMED_WAITING** | 限时等待，等超时自动醒（sleep()、wait(time)、join(time)） |
| **TERMINATED** | 终止，线程执行完了 |

#### 2. 状态转换图（核心！）

```
      new Thread()
           ↓
         [NEW]
           ↓  start()
         [RUNNABLE] ←──────────┐
           /   \                │  拿到锁
  CPU时间片完   拿到锁           │
          │       │             │
          │   [BLOCKED]  抢锁失败
          │       │             │
          │       └─────────────┘
          │
          │  wait()/join()/park()
          ↓
       [WAITING] ←──────────────┐
          │                     │
          │  notify()/          │
          │  LockSupport.unpark()│
          └─────────────────────┘
          │
          │  sleep(time)/wait(time)
          ↓
    [TIMED_WAITING] ←──────────┐
          │                     │
          │  超时了 / 被唤醒     │
          └─────────────────────┘
          │
          │  执行完 / 异常退出
          ↓
      [TERMINATED]
```

**面试常考：BLOCKED vs WAITING 的区别？**
> - **BLOCKED**：等着拿锁（别人拿着锁不放，我进不去同步块）
> - **WAITING**：拿到锁之后，自己主动wait()等着，等着别人notify()唤醒我
>
> 简单说：BLOCKED是"想进门但门锁着"，WAITING是"进门了但自己想在门口等会儿"。

## 常见面试题

### 1. 什么是Java内存模型？

**回答思路：**
> Java内存模型（JMM）是JVM定义的一套规则，用来屏蔽不同硬件和操作系统的内存访问差异，让Java程序在各种平台下都能有一致的内存访问效果。
>
> 这套规则主要围绕**原子性、可见性、有序性**三大特性建立，核心是**先行发生（happens-before）原则**。

---

### 2. volatile关键字的作用和原理？

**回答思路：**
> volatile有两大作用：
>
> 1. **保证可见性**：对volatile变量的修改会立即写回主内存，并且让其他线程的缓存失效，下次读取必须重新从主内存读
> 2. **禁止指令重排序**：volatile变量前后的指令不能重排序，通过内存屏障实现
>
> **原理**：volatile变量的写操作会在汇编层面加一个`lock`前缀，这个前缀会：
> - 把当前CPU缓存行的数据立即写回主内存
> - 让其他CPU缓存了这个内存地址的数据失效
>
> **注意**：volatile不能保证原子性！比如`a++`还是有并发问题。

---

### 3. happens-before原则是什么？说几个常用的？

**回答思路：**
> happens-before是JMM用来判断"一个操作的结果对另一个操作是否可见"的规则。如果A happens-before B，那么A的修改对B一定可见。
>
> 常用的5个规则：
> 1. **程序次序规则**：同一个线程内，前面的先行于后面的
> 2. **管程锁定规则**：unlock先行于后面对同一个锁的lock
> 3. **volatile变量规则**：写先行于读
> 4. **线程启动规则**：start()先行于线程内的所有操作
> 5. **传递性**：A先于B，B先于C → A先于C

---

### 4. 双重检查锁的单例模式为什么要加volatile？

**回答思路：**
> 因为`new Singleton()`不是原子操作，可以拆成三步：
> 1. 分配内存空间
> 2. 初始化对象
> 3. 把instance指向内存地址
>
> 如果发生指令重排序，可能变成1→3→2。如果执行完3后另一个线程进来，发现instance不为null就直接返回了，但对象还没初始化！
>
> volatile可以**禁止指令重排序**，确保1→2→3的顺序，避免拿到半初始化的对象。

---

### 5. 说说你对主内存和工作内存的理解？

**回答思路：**
> JMM把内存分成两部分：
> - **主内存**：所有线程共享，所有变量都存在主内存
> - **工作内存**：每个线程私有，保存了该线程用到的变量的副本
>
> 线程不能直接操作主内存，只能操作自己工作内存里的副本，线程之间也不能互相访问工作内存，变量传递必须通过主内存。
>
> 这就是可见性问题的根源：一个线程改了自己工作内存的副本，还没写回主内存，其他线程看不到。

---

### 6. Java线程有哪几种状态？BLOCKED和WAITING的区别？

**回答思路：**
> Java线程有6种状态：NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED。
>
> **BLOCKED vs WAITING：**
> - BLOCKED是**阻塞等锁**：想进同步块但锁被别人拿了，被动等待
> - WAITING是**主动等待**：拿到锁之后，自己主动调用wait()/join()等方法，等着其他线程唤醒
>
> 类比：BLOCKED是想进办公室但门被锁了在门外等；WAITING是已经进办公室了，想等个人再干活，在里面沙发上等。

---

### 7. 说说synchronized和volatile的区别？

**回答思路：**
> | 特性 | synchronized | volatile |
> |------|-------------|----------|
> | 原子性 | 保证 | 不保证 |
> | 可见性 | 保证（unlock前写回主内存） | 保证 |
> | 有序性 | 保证（锁内可以重排，但锁外看不到） | 保证（禁止重排序） |
> | 阻塞 | 会阻塞线程 | 不会阻塞 |
> | 适用场景 | 原子性保障、临界区 | 状态标志、禁止重排序 |

## 本章学习建议

1. **先搞懂为什么**：不是先记概念，而是先理解"为什么需要JMM？没有会怎么样？"
2. **三大特性是核心**：原子性、可见性、有序性，每个都要懂是什么、怎么保证
3. **volatile是高频考点**：作用、原理、和synchronized的区别、单例模式的应用
4. **happens-before是判断依据**：判断可见性不要猜，套规则就行
5. **线程状态要画图**：6种状态的转换关系，自己画一遍就记住了

> 💡 **学习心法**：JMM不是什么黑科技，本质上就是"在多线程环境下，一个线程改了变量，什么时候另一个线程能看到"的约定。把自己想象成两个不同的线程，站在不同CPU的角度去看内存，你就懂了！
