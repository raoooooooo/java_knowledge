## 一、Agent 类 ★

### Q1 Agent 是什么？和普通调用大模型有什么区别？
**答**：Agent = LLM（大脑）+ 规划 + 记忆 + 工具 + 循环，控制权交给 LLM 自主决策。普通调用大模型是「一问一答无状态无行动」；Agent 能自主感知-规划-调工具-执行-观察-迭代直到完成目标。
**话术**：Agent 的本质是「控制权交给 LLM」。开发者写死流程的是 Workflow，LLM 自己决定下一步的是 Agent。生产常混合：外层 Workflow 控骨架，节点内 Agent 处理不确定子任务。
**追问**：Agent 和 Workflow 区别？答：Workflow 流程写死确定（分支由规则决定），Agent 流程由 LLM 自主决定（非确定，能动态选工具路径）。

### Q2 Agent 的运行循环是怎样的？
**答**：while 未完成：组装上下文 -> 调模型 -> 若调工具则执行后把结果作为 Observation 回灌继续循环 -> 若给最终答案则结束。工具调用是循环引擎，模型决定下一步是 Agent 自主性来源。设最大步数防死循环。
**追问**：循环什么时候终止？答：模型输出最终答案（无工具调用）/ 达最大步数 / 超时 / 重复检测命中 / 用户中断。

### Q3 ReAct、Plan-Execute、Reflexion 区别？★
**答**：ReAct 边想边做（Thought-Action-Observation 交替）；Plan-Execute 先规划再执行（适合复杂长任务，减少中途卡死）；Reflexion 做错复盘再做（自我改进）。常组合：Plan-Execute 规划执行，Reflexion 失败时反思修正。
**话术**：ReAct 是「边想边做」，Plan-Execute 是「先想好再做」，Reflexion 是「做错了复盘再做」。
**追问**：ReAct 局限？答：一步一停慢贵、线性推理不能回退。复杂任务用 Plan-Execute。

### Q4 Agent 怎么防死循环？★
**答**：多重：最大步数兜底（必须有）、超时、重复调用检测（连续调同工具同参数=卡住）、工具失败重试次数限制。监控平均步数，飙升=质量下降信号。
**话术**：没有步数限制的 Agent 一定会死循环烧钱。生产必须有 maxSteps，且监控平均步数--步数突然涨说明质量下降或快死循环了。

### Q5 Agent 的短期记忆和长期记忆怎么实现？
**答**：短期=上下文窗口内对话历史（快但有限、会丢）；长期=外部存储（向量库/图谱/KV/文件），按需检索注入。长期主流用向量记忆库（RAG 应用于记忆）。检索质量决定长期记忆有没有用。
**追问**：记忆管理三问？答：写什么（只记有价值的偏好/决策/事实/教训）、怎么找（语义检索注入，要优化检索）、何时忘（淘汰过时+反思合并泛化防膨胀+合规删除）。全存会噪音爆炸。

### Q6 上下文快满了怎么办？★
**答**：多策略：自动压缩旧内容成摘要腾空间、滑动窗口截断、关键信息锚定保留、子 Agent 隔离子任务只回传结论、裁剪工具返回结果。不是简单截断，是分级管理。
**追问**：什么是子 Agent 隔离？答：子任务用独立上下文处理海量细节，只回传最终结论，主上下文保持干净。防爆炸+防污染+可并行。

### Q7 Agent 怎么保证输出质量？
**答**：多层：Self-Correction（Actor 生成-Critic 评审-不通过修正循环）、客观 Verifier（规则/编译/测试校验）、LLM-as-Judge 打分、黄金评测集回归防退化。能客观校验的优先客观（如代码 Agent 看测试通过率）。
**话术**：传统软件靠单测保证质量（确定性），Agent 靠自我反思+客观校验+评测回归（非确定性）。给非确定性套上确定性的工程外壳。

### Q8 什么时候用多 Agent？
**答**：任务可清晰拆解、需多专家视角、单 Agent 上下文/角色过载才用多 Agent。简单线性任务单 Agent + 工具更优。不是越多越好，每个 Agent 有成本，过多难协调慢贵。
**追问**：四种多 Agent 架构？答：层级（Supervisor 调度）、网络（点对点）、辩论（多方案+裁判）、编排（并行 Worker+聚合）。看任务选，常混合。

## 二、MCP / 协议类 ★

### Q9 MCP 是什么？解决什么问题？
**答**：Model Context Protocol，Anthropic 2024.11 提出的开放协议，标准化 Agent 与工具/数据源的连接，把 M×N 集成变成 M+N。架构是 Host/Client/Server，能力原语是 Tools/Resources/Prompts。「AI 应用的 USB-C」。
**追问**：MCP 三大原语？答：Tools（可执行函数，模型决定调）、Resources（可读数据，应用控制）、Prompts（预置模板，用户触发）。后续还有 Sampling/Roots/Elicitation。

### Q10 MCP 传输方式有哪些？
**答**：stdio（本地子进程，低延迟简单，最常用）和 Streamable HTTP（远程，2025-03 spec 引入取代旧的 HTTP+SSE）。旧 HTTP+SSE 双连接难负载均衡，新 Streamable HTTP 单端点可灵活返回 JSON 或升级 SSE 流。
**追问**：为什么从 HTTP+SSE 改 Streamable HTTP？答：旧的双连接难负载均衡、状态重；新单端点可返回 JSON 或升级 SSE 流，更适合生产。

### Q11 A2A 和 MCP 区别？它们竞争吗？★
**答**：不竞争、互补。MCP 是 Agent<->工具，A2A 是 Agent<->Agent。完整链路 `Agent A --A2A--> Agent B --MCP--> 工具`。MCP 解决「Agent 怎么用工具」，A2A 解决「Agent 之间怎么对话」。
**追问**：ACP 和 A2A 区别？答：A2A 偏同步+流式（JSON-RPC/SSE）；ACP 偏异步、企业级，可对接 Kafka/RabbitMQ 做长任务跨组织。

### Q12 AG-UI 解决什么？
**答**：标准化 Agent<->前端交互，用标准事件流（text-message-chunk/tool-call/state-snapshot 等）让任意前端渲染任意 Agent 的过程。三者互补：MCP 向下接工具、A2A/ACP 横向连 Agent、AG-UI 向上对用户。

## 三、工程化类 ★ Java 主场

### Q13 Agent 怎么做生产架构？
**答**：无状态运行时 + 有状态存储外置：Agent 运行时无状态可水平扩展，会话历史/记忆/任务状态外置到 Redis/DB/向量库。加 Agent 网关（鉴权限流熔断审计多模型适配）+ 异步长任务队列 + 多副本高可用。分布式系统老套路迁移。
**话术**：这就是分布式系统老套路，AI 特有的是 token 成本和非确定性要加可观测和评测。
**追问**：为什么运行时要无状态？答：有状态实例无法水平扩展（某用户状态在某实例，请求到别的实例丢）。无状态任意实例处理任意请求可扩缩容。

### Q14 LLM 应用为什么需要专门的可观测？观测什么？
**答**：非确定性+内容驱动+按 token 计费，传统 APM 不够。要 Trace（调用树每步输入输出）、Token 成本、延迟（TTFT）、错误率、质量（幻觉率）、业务（任务完成率/平均步数）。工具：Langfuse/LangSmith/OTel GenAI。
**追问**：OTel GenAI 语义约定是什么？答：OpenTelemetry 对 LLM 调用的标准埋点规范，让 AI Trace 和传统服务 Trace 用同一套 OTel 体系串联，跨厂商不绑定。

### Q15 Agent 安全有哪些特有风险？怎么防？
**答**：Prompt 注入（指令数据隔离+审核）、过度自主（人在环+确认+沙箱）、数据泄露（PII 脱敏+外发确认+不出域）、工具滥用（权限+配额+审计）、幻觉行动（关键操作前校验）。核心最小权限。
**话术**：Agent 能行动，风险远大于纯文本。核心是最小权限--即使被注入/幻觉也限制危害范围。高危操作（删数据/付款/外发）必须人在环确认。
**追问**：Prompt 注入能完全防住吗？答：不能，自然语言无法像 SQL 参数化完全转义。靠多层提高门槛+最小权限限制危害，无银弹。

### Q16 多模型路由解决什么？怎么路由？
**答**：成本（简单任务用小模型）、能力互补、容灾（主挂切备）、合规（敏感私有化）。按任务路由（难度分流）、级联（小模型先试再升级大）、降级（主挂切备）、私有化分流。配合缓存/压缩降本。
**追问**：级联为什么省钱？答：大部分简单请求小模型搞定，不确定才升级大模型，省大模型调用费。

### Q17 Agent 怎么评测和灰度？
**答**：离线评测集+LLM-as-Judge+回归对比，指标看任务完成率/工具准确率/平均步数/Token/接管率。灰度：评测验证->注册新版本->小流量灰度监控指标->达标全量，不达标回滚。配置中心切版本分钟级回滚。
**追问**：Agent 的「单测」是什么？答：黄金评测集（典型问题+期望输出）+ LLM-as-Judge 打分 + 回归对比。Bad Case 持续纳入集子。

### Q18 怎么降 LLM 成本？★
**答**：三板斧：压缩上下文（减输入 token）、用小模型（降单价，级联让小先试）、缓存（精确+语义复用）。配合批处理 API（离线半价）、Prompt 压缩、上下文裁剪、量化蒸馏（私有化）。
**追问**：语义缓存有什么坑？答：相似度阈值设错返回不相关、知识更新要清缓存、敏感数据别缓存、个性化别缓存。

### Q19 私有化部署模型慢怎么办？
**答**：推理加速：首选 vLLM（PagedAttention+连续批处理，吞吐高、兼容 OpenAI API）。显存有限用量化（INT8/INT4），固定任务用蒸馏小模型。
**追问**：vLLM 为什么快？答：PagedAttention（分页管理 KV-cache 减少显存碎片）+ 连续批处理（动态拼批 GPU 利用率高），吞吐比原生高数倍。

## 四、系统设计题套路 ★

### Q20 设计一个企业知识库问答系统 / 智能客服

**答题套路**（不只堆技术栈，要讲选型理由+工程化+取舍）：

1. **需求理解**：复述需求，明确边界（多用户/溯源/并发/合规）。
2. **整体架构**：离线建库 + 在线检索生成 + 工程化（网关/可观测/安全/评测/成本）。
3. **核心选型+理由**：切分/Embedding/向量库/检索/LLM/框架，每个说为什么。
4. **工程化考量**：
   - 高可用：无状态多副本+降级。
   - 可观测：Trace/Token/质量。
   - 安全：PII 脱敏+注入防护+审核。
   - 评测：黄金集+RAGAS+灰度。
   - 成本：压缩+缓存+小模型。
5. **容量性能**：向量库按数据量/QPS、缓存热门、流式。
6. **取舍**：简单用 RAG 够别上 Agentic RAG；按场景选技术。
7. **演进**：MVP 先简单 RAG，后续按 Bad Case 优化。

> 💡 **系统设计题的关键**：讲选型理由 + 工程化考量（容量/性能/安全/可观测/成本）+ 取舍 + 演进路线。体现架构思维，不只堆技术栈。

## 六、资料勘误与重点提醒

1. **面试别只背答案**：资料给的标准答案要理解原理。背答案一追问露馅，懂原理能举一反三。27/28 章是辅助理解不是背诵材料。
2. **「我会」vs「我做过」**：面试官爱问项目。没做过要能讲合理方案+踩坑，别硬编「做过」被追问穿帮。动手跑 Demo 是关键。
3. **答案带取舍**：资料常给唯一答案。实际面试要看场景，讲「什么情况用 A 什么情况用 B」更体现深度。
4. **追问才是考点**：资料常只给主问题答案。面试官追问（为什么/怎么办/坑）才是区分度，准备时预想追问。27/28 章每题都给了追问。
5. **工程化是 Java 优势**：资料和 Python 教程常重原理轻工程化。Java 工程师要讲工程化（19-24）作为差异化，这是 Python 候选人不一定有的。
6. **生态变化快**：AI 生态每月在变（模型/框架/协议）。资料截至 2026 中，面试前关注最新动态，体现持续学习。

## 七、全系列总结

恭喜你读完全系列 28 章。回顾能力地图：

```
入门(01-04)    会调API、写Prompt、做Function Calling
RAG(05-08)     能搭、能调、能评测、能排障RAG系统
Agent核心(09-13) 懂Agent Loop、上下文、记忆、工具、反思
框架(14-18)    选对Spring AI/LangChain4j、编排复杂流程、多Agent
工程化(19-24)  能上线、能运维、能合规、能降本（Java主场）
场景冲刺(25-28) 答透面试、做系统设计、规划学习
```

**核心认知**：
- Agent 开发主要是**工程**不是算法，Java 工程师的优势在**工程化**。
- AI 应用是「概率性系统」，工程化的核心是「给非确定性套上确定性的工程外壳」--评测、护栏、可观测、人在环。
- 你的分布式系统、Spring、网关、限流、安全经验，直接迁移到 AI 工程化，这是你的差异化竞争力。

**下一步**：动手跑 Demo、准备项目故事、关注生态动态。面试时讲「我做过、踩过这个坑、这么解决的」--这才是最强的回答。

祝面试顺利。
