# 01 - Agent 开发全景与面试能力地图

> 本章是全系列的「地图」。不写一行代码，先回答三个问题：Java 工程师为什么要学 Agent？Agent 开发和传统后端开发到底哪里不同？面试官会怎么问、想听什么？看懂这章，后面学什么、怎么答就有方向了。

---

## 一、岗位现状：Java 面试里 AI 占了一半

- **真实趋势**：2025 年起，中高级 Java 后端（尤其业务平台、中间件、SaaS 方向）面试中，AI/Agent 相关问题占比显著上升，很多场次占到一半。常见问法：「你们系统接入大模型了吗」「知识库怎么做的」「RAG 检索不准怎么调」「Agent 是怎么跑起来的」。
- **背后的驱动**：企业从「有没有 AI」转向「AI 能不能落地」。落地的活--会话管理、限流、可观测、灰度、安全合规--本质上就是后端工程，这正是 Java 工程师的舒适区。
- **分化**：纯 CRUD 岗位在减少，会 AI 工程化的 Java 工程师溢价明显。「会用 Spring AI 搭一个能上线的 Agent」是当下的差异化标签。

> 💡 **面试金句**：算法工程师解决「模型行不行」，Java 工程师解决「应用能不能上线」。我选后者作为切入点--把分布式系统和 Spring 生态的经验，用到 AI 应用的工程化上。

---

## 二、Java 工程师学 Agent 的独特优势

很多人怕「我不是算法背景，能学好吗」。其实 Agent 开发主要是**工程**，不是炼丹：

| 传统后端能力 | 在 Agent 开发里的对应 |
|------------|---------------------|
| 分布式系统、微服务 | Agent 工程化架构、多 Agent 协作 |
| Spring 生态、AOP/拦截器 | Spring AI Advisor 链（本质就是拦截器） |
| 网关、限流、熔断 | Agent 网关、模型限流降级 |
| 可观测（SkyWalking/Prometheus） | LLM 可观测（Trace/Token/成本） |
| 事务、状态机 | Agent 状态管理、会话持久化、断点恢复 |
| 安全、权限 RBAC | Prompt 注入防护、内容审核、数据脱敏 |
| 灰度发布、注册中心 | Agent 版本管理、灰度、A/B |

- **模型层不是你的主战场**：选模型、调 prompt、评测效果，理解原理够用即可，不需要自己训模型。
- **你的主战场是工程化**：把「能跑的 Demo」变成「能上线、能运维、能合规的系统」。这块 Python 生态反而不如 Java 成熟（企业级治理）。
- **面试卖点**：能讲清楚「我不仅会调 API，还知道怎么把它做成生产级服务」。

## 三、Agent 开发和传统后端开发的本质差异 ★

> 这是理解整个 AI 工程化的钥匙，也是面试最爱问的「认知题」。

### 3.1 确定性 vs 非确定性

| 维度 | 传统后端 | Agent/LLM 应用 |
|------|---------|---------------|
| 逻辑 | `if/else` 写死，**确定** | 模型推理，**概率性、非确定** |
| 输入输出 | 强类型、schema 固定 | 自然语言，结构需约束 |
| 错误 | 异常可枚举、可单元测试 | 幻觉、跑偏、格式错，难穷举 |
| 调试 | 看日志、断点 | 看 Trace、回放 prompt、分析 token |
| 质量 | 单测覆盖 + 压测 | 评测集 + LLM-as-Judge + 在线 AB |

### 3.2 这个差异带来的工程挑战

1. **不能靠单元测试保证质量**：同一输入可能不同输出，得靠「评测集」和「抽样人工/LLM 打分」。
2. **延迟和成本不可控**：一次 LLM 调用可能 2 秒也可能 30 秒，token 花费随 prompt 长度波动，必须做超时、限流、成本预算。
3. **错误处理要换思路**：传统是「失败重试」，Agent 是「失败要让模型自我修正」（把错误信息喂回去让它改）。
4. **可观测维度变了**：不只看 QPS/RT/错误率，还要看 token 成本、prompt 内容、幻觉率、任务完成率。
5. **安全模型变了**：用户输入可能「劫持」模型行为（Prompt 注入），输出可能违规，工具调用可能越权。

> 💡 **面试金句**：传统后端是「确定性系统」，靠单测和强 schema 保证质量；Agent 是「概率性系统」，靠评测集、Trace、护栏和人在环来治理。工程化的核心就是「给非确定性套上确定性的工程外壳」。

### 3.3 类比记忆

- 传统后端 = **精密齿轮**：每个齿咬合确定，坏了换齿。
- Agent = **训狗师 + 狗**：狗（模型）有自主性，你不能规定它每一步，但能用护栏（指令、工具、审核、人在环）引导它大致做对。

## 四、Agent 开发技术栈全景（面试可背版）

```
模型层    → OpenAI / Claude / 通义 / DeepSeek / GLM（闭源+国产开源）
            ↓ 提供能力：对话、Embedding、Function Calling
框架层    → Spring AI / LangChain4j / Spring AI Alibaba
            ↓ 提供抽象：ChatClient、Advisor、Tool、VectorStore、Memory
能力层    → RAG（检索增强）、Function Calling（工具）、Memory（记忆）、Planning（规划）
            ↓ 组合成 Agent
协议层    → MCP（接工具）、A2A/ACP（Agent 间通信）、AG-UI（Agent-前端）
            ↓ 标准化互通
工程层    → 网关/限流、可观测、安全护栏、模型路由、评测灰度、会话持久化
            ↓ 上线运维
基础设施  → K8s/Docker/MQ/Redis/向量库
```

- **模型层**：能力来源。国产首选通义/DeepSeek/GLM（合规、可私有化、便宜）。
- **框架层**：Java 两强 Spring AI + LangChain4j。国内加 Spring AI Alibaba。
- **能力层**：RAG（给模型外挂知识）、Function Calling（给模型手）、Memory（给模型记忆）、Planning（让模型会拆任务）。
- **协议层**：MCP 是 2024 起最热的工具标准，A2A 是 Agent 间通信标准。
- **工程层**：你的主场。

## 五、面试能力地图：面试官怎么问、想听什么

> 把面试官的提问分成四类，每类对应你要准备的内容。

### 5.1 概念认知类（考你懂不懂）
- 问：「Agent 是什么？和普通调用大模型有什么区别？」
- 想听：Agent = LLM + 规划 + 记忆 + 工具 + 循环；控制权交给模型自主决策。
- 准备：03（Agent 核心）+ 09（Agent Loop）。

### 5.2 原理深挖类（考你知不知道为什么）
- 问：「RAG 检索为什么不准？怎么优化？」「为什么需要 Rerank？」
- 想听：根因分析（切分/Embedding/召回）+ 多种优化手段 + 取舍。
- 准备：05/06（RAG）+ 02（倒排/向量原理）。

### 5.3 项目落地类（考你做过没）★ 最难造假
- 问：「你们 RAG/Agent 怎么落地的？踩过什么坑？」「为什么这么选型？」
- 想听：具体技术方案 + 选型理由 + 真实踩坑 + 量化收益。
- 准备：25（场景实战）+ 每章的「生产踩坑」小节。**没做过也要能讲出合理方案和踩坑**。

### 5.4 系统设计类（考你能不能架构）
- 问：「设计一个企业知识库问答系统」「设计一个智能客服」
- 想听：整体架构 + 关键技术选型 + 容量/性能/安全/可观测考量 + 取舍。
- 准备：19（工程化架构）+ 25（系统设计题）。

## 六、学习心法（怎么高效准备）

1. **原理 + 代码 + 面试题三位一体**：只看原理不会答，只刷题不懂原理一追问就露馅。本系列每章三者齐全。
2. **动手跑 Demo**：哪怕只跑通 Spring AI 调通义千问 + 一个 RAG，面试时底气完全不同。「我做过」>「我看过」。
3. **准备 2-3 个项目故事**：哪怕是小 Demo，也要能讲出「背景→方案→选型理由→踩坑→收益」。面试官最爱追问这个。
4. **关注生态动态**：MCP、Spring AI、通义这些迭代很快，面试可能问「你关注哪些新东西」，体现持续学习。
5. **用 Java 视角降维**：被问 Python 生态的 LangChain 时，主动说「我们 Java 侧用 LangChain4j/Spring AI，原理相通」体现你的判断。

## 七、常见面试题（认知类）

1. **Java 工程师为什么要学 Agent？你的优势在哪？**
   企业从「有没有 AI」转向「能不能落地」，落地的工程化（会话、限流、可观测、灰度、安全）是 Java 后端主场。我的优势是分布式系统和 Spring 生态经验，能直接迁移到 AI 工程化，不需要和算法拼模型。

2. **Agent 开发和传统后端开发最大的区别是什么？**
   确定性 vs 非确定性。传统后端 if/else 写死可单测，Agent 靠模型推理概率输出，质量靠评测集和护栏而非单测，错误靠让模型自我修正而非简单重试，可观测还要看 token 和幻觉率。核心是「给非确定性套上确定性的工程外壳」。

3. **Agent 开发的核心技术栈有哪些？**
   模型层（OpenAI/通义/DeepSeek）+ 框架层（Spring AI/LangChain4j）+ 能力层（RAG/Function Calling/Memory/Planning）+ 协议层（MCP/A2A）+ 工程层（网关/可观测/安全/灰度）。Java 侧主力是 Spring AI 和 LangChain4j。

4. **你了解 Agent 开发这块有哪些新技术趋势？**
   MCP 标准化 Agent 接工具、A2A 标准化 Agent 间通信、Spring AI 成为 Java AI 框架事实标准、Agentic RAG（RAG 与 Agent 融合）、长上下文模型降低 RAG 依赖、可观测和评测工程化（Langfuse/LLM-as-Judge）。

5. **如果让你从零搭一个企业知识库问答，你怎么规划？**
   （系统设计题，简版）文档切分+Embedding 入向量库→检索+Rerank→拼 Prompt 调模型→加引用溯源。工程上：会话管理、可观测（Trace/成本）、安全（PII 脱敏、Prompt 注入防护）、评测集防退化、灰度发布。详细见 25 章。

## 八、资料勘误与重点提醒

1. **「Agent 工程师 = 算法工程师」是误解**：很多资料把 Agent 开发和模型训练混为一谈。Agent 开发主要是**应用工程**，调模型 API、搭 RAG、编排流程、做工程化，不要求训模型。Java 工程师完全能切入，优势在工程化。
2. **「确定性系统」的测试思维不能照搬**：传统用单测覆盖率保证质量，到 Agent 里失效（非确定性输出）。必须改用评测集 + LLM-as-Judge + 在线 AB。这是认知题，面试常考。
3. **别只学 Python 生态**：大量教程是 Python 的（LangChain）。Java 工程师面试要能讲 Spring AI / LangChain4j，这是你的差异化。Python 概念可借鉴但落地用 Java。
4. **「会用」和「能上线」差一个工程化**：能调 API ≠ 能上线。会话持久化、限流降级、可观测、安全、评测灰度这些才是面试区分度，也是本系列第五篇重点。
