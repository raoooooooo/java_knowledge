# 22 - 模型路由与降级

> 单一模型有成本、能力、容灾、合规多重局限。多模型路由是生产标配。本章讲怎么按任务路由、级联降级、成本优化、私有化混合。呼应 13 章概念，讲 Java 落地。

---

## 一、为什么需要多模型 ★

| 需求 | 单模型的问题 | 多模型解决 |
|------|------------|-----------|
| **成本** | 全用大模型贵 | 简单任务用小模型便宜 |
| **能力互补** | 一个模型不万能 | 不同模型各有所长 |
| **容灾** | 主模型挂全挂 | 自动切备用 |
| **合规** | 敏感数据不能出 | 部分私有化部署 |

> 💡 **面试金句**：多模型路由解决成本（简单任务用小模型）、能力互补（各模型所长）、容灾（主挂切备）、合规（敏感私有化）。生产标配，不是可选。

---

## 二、模型路由策略 ★

### 2.1 按任务路由

- 分类器/路由模型判断任务难度/类型，分发到合适模型。
- 简单（闲聊/分类）-> 小模型（qwen-turbo/便宜）。
- 复杂（推理/代码）-> 大模型（qwen-plus/deepseek-reasoner）。
- 多模态 -> 视觉模型（qwen-vl）。

```
用户请求 -> [路由判断] --简单--> 小模型（便宜快）
                    |--复杂--> 大模型（强）
                    |--多模态--> 视觉模型
                    |--敏感--> 私有化模型
```

### 2.2 级联（Cascade）★ 降本利器

- 先用小模型试，不确定/失败再升级大模型。
- 大部分简单请求小模型就搞定，省钱。
- 阈值：小模型置信度低于 X 或明确「无法处理」才升级。

```
请求 -> 小模型 --置信度高/成功--> 返回
              |--不确定/失败--> 升级大模型 -> 返回
```

### 2.3 降级（Fallback）

- 主模型超时/限流/挂了，自动切备用模型。
- 模型 A 挂 -> 切 B -> 切 C，保证可用。
- 配合熔断（主模型连续失败触发熔断，一段时间直接走备用）。

### 2.4 私有化分流

- 敏感请求路由到私有化部署模型（数据不出域）。
- 非敏感走云端 API（降本）。
- 按数据敏感度路由。

## 三、成本优化手段 ★

### 3.1 缓存

- **精确缓存**：相同请求复用结果（适合固定问答 FAQ）。
- **语义缓存**：相似请求（语义相近）复用结果，用 Embedding 判断相似度。
- Redis 存「Query 向量 -> 结果」，命中省一次 LLM 调用。

```java
// 语义缓存思路
float[] qVec = embeddingModel.embed(query);
CacheEntry hit = cache.findSimilar(qVec, threshold);  // 找相似缓存
if (hit != null) return hit.result;   // 命中直接返回
String result = llm.call(query);
cache.store(qVec, result);            // 存入缓存
```

### 3.2 Prompt 压缩

- 压缩冗长 prompt（LLMLingua 等，06 章），减少输入 token。
- 少传历史（压缩/滑动窗口，10 章）。

### 3.3 批处理 API

- 部分模型支持批处理（batch）API，异步批量处理，单价低很多（如半价）。
- 适合非实时场景（离线数据处理、评测）。

### 3.4 小模型优先

- 简单任务用小模型（turbo 系列），复杂才用大。
- Embedding/Rerank 用专门小模型，别用大模型干。

### 3.5 上下文裁剪

- 工具结果只留关键字段、检索结果 Rerank 后取 Top-K、别一股脑塞历史。
- 减少 token 就是省钱。

> 💡 **面试金句**：成本优化三板斧：压缩上下文（减输入）、用小模型（降单价，级联让小模型先试）、缓存（复用结果，语义缓存命中省一次调用）。配合批处理 API（离线半价）。

## 四、Java 实现：模型路由层

```java
// 抽象统一调用层，屏蔽模型差异
public interface LlmRouter {
    String call(String prompt, TaskContext ctx);
}

public class SmartLlmRouter implements LlmRouter {
    private ChatModel small;   // qwen-turbo
    private ChatModel large;   // qwen-plus
    private ChatModel fallback;// 备用

    public String call(String prompt, TaskContext ctx) {
        // 1. 语义缓存
        String cached = cache.get(prompt);
        if (cached != null) return cached;

        // 2. 按任务路由
        ChatModel model = route(ctx);   // 简单用小，复杂用大，敏感用私有

        // 3. 调用 + 降级
        try {
            return callWithFallback(model, prompt);
        } catch (Exception e) {
            return callWithFallback(fallback, prompt);  // 降级
        }
    }

    private ChatModel route(TaskContext ctx) {
        if (ctx.sensitive) return privateModel;      // 敏感私有化
        if (ctx.complex) return large;               // 复杂大模型
        return small;                                 // 简单小模型
    }
}
```

- Spring AI 的 ChatModel 抽象让换模型只改 Bean，路由层在此基础上加路由/降级/缓存逻辑。
- 也可用 Advisor（15 章）在调用前做路由/缓存横切。

## 五、模型版本管理与灰度

### 5.1 版本管理

- 生产用固定版本号（`qwen-plus-20260715`）而非别名。
- 不同版本并存：新版本灰度，老版本兜底。
- 配合配置中心动态切换版本。

### 5.2 灰度

- 新模型先小流量灰度，监控指标（准确率/成本/延迟）。
- 达标全量，不达标回滚老版本。
- 配合评测集（23 章）验证新版本不退化。

### 5.3 回滚

- 模型出问题一键切回老版本。
- 版本可配置，不重启切换。

## 六、私有化与混合云

### 6.1 私有化部署

- 开源模型（Qwen/DeepSeek/GLM 开源版）+ vLLM 推理加速自部署（16 章）。
- 敏感数据不出域，合规。
- 代价：GPU 成本、运维、效果可能略逊。

### 6.2 混合云架构

```
[敏感请求] -> 私有化模型（数据不出域）
[普通请求] -> 云端 API（降本、能力强）
```

- 按数据敏感度路由，兼顾合规和成本。
- 私有化做敏感，云端做普通和复杂（云端旗舰模型更强）。

## 七、生产踩坑

1. **全用大模型**：成本爆炸。简单任务用小模型，级联让小先试。
2. **无降级**：主模型挂全挂。必须自动切备用。
3. **别名漂移**：用别名厂商更新导致输出变。固定版本号。
4. **缓存命中错**：语义缓存相似度阈值设错，返回不相关结果。调好阈值+抽检。
5. **新模型不评测就上**：准确率可能退化。灰度+评测验证（23 章）。
6. **私有化不做加速**：自部署开源模型慢，用 vLLM/TGI。
7. **路由判断错**：路由分类器不准，简单任务用大模型浪费。调好路由。

## 八、常见面试题

1. **为什么要多模型路由？**
   成本（简单任务用小模型）、能力互补（各模型所长）、容灾（主挂切备）、合规（敏感私有化）。生产标配。

2. **模型路由有哪些策略？**
   按任务路由（分类器判难度分发）、级联（小模型先试不确定再升级大）、降级（主挂切备）、私有化分流（敏感走私有化）。配合缓存/Prompt 压缩降本。

3. **什么是级联？为什么省钱？**
   先用小模型试，不确定/失败才升级大模型。大部分简单请求小模型搞定，省大模型调用费。设置信度阈值决定升级。

4. **主模型挂了怎么办？**
   自动降级切备用模型（A->B->C）。配合熔断（主模型连续失败触发熔断，一段时间直接走备用）。保证可用性。

5. **语义缓存是什么？有什么坑？**
   相似请求复用结果（用 Embedding 判断相似度）。坑：相似度阈值设错返回不相关结果、缓存失效（知识更新要清缓存）、敏感数据别缓存。抽检命中率。

6. **怎么降 LLM 成本？**
   三板斧：压缩上下文（减输入 token）、用小模型（简单任务 turbo，级联让小先试）、缓存（精确+语义复用）。配合批处理 API（离线半价）、Prompt 压缩、上下文裁剪。

7. **敏感数据怎么处理模型调用？**
   私有化分流：敏感请求路由到私有化部署模型（数据不出域），非敏感走云端 API。混合云兼顾合规和成本。PII 脱敏后再送模型（21 章）。

8. **新模型怎么上线？**
   固定版本号 -> 评测集验证不退化（23 章）-> 小流量灰度监控指标 -> 达标全量，不达标回滚。配置中心动态切换版本，不重启。

## 九、资料勘误与重点提醒

1. **「全用最强模型」是成本误区**：资料示例常默认用最强模型。生产简单任务用小模型，级联让小先试，能省大部分成本。
2. **「别名模型方便」是坑**：资料示例常用 `qwen-plus` 别名。厂商更新别名导致输出漂移、评测失效。生产固定版本号。
3. **「语义缓存随便用」有坑**：语义缓存相似度阈值设错返回不相关结果、知识更新缓存不失效返回旧答案、敏感数据不该缓存。资料常不讲这些。
4. **「私有化一定更好」不严谨**：私有化数据不出域更安全，但开源版效果可能略逊旗舰、运维和 GPU 成本高。要评估 ROI，混合云兼顾。
5. **降级少强调熔断**：资料讲降级常只说「切备用」。实际要配合熔断（主模型连续失败触发熔断直接走备用，否则每次都先试主再降级浪费）。
6. **新模型不评测就上是坑**：资料讲灰度少强调评测。新模型可能准确率退化/对齐变（更啰嗦/不安全），必须评测集验证再灰度。
