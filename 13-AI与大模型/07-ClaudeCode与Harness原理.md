# Claude Code 与 Harness 原理

> 本章用一个真实的生产级 Agent--**Claude Code**（Anthropic 官方 CLI Agent）--把前面所有概念串起来：Agent Loop、上下文工程、工具系统、Skill、子 Agent、Hooks、权限沙箱，以及背后的 **Harness** 运行时。看懂这个真实案例，Agent 原理就落地了。

---

## 一、核心概念

### 1.1 Claude Code 是什么

- **定位**：Anthropic 官方的 **CLI Agent / 编码 Agent**，运行在终端，能读写文件、跑命令、搜索代码、调子 Agent，自主完成软件工程任务。
- **形态**：终端 CLI、桌面应用、Web（claude.ai/code）、IDE 插件（VS Code/JetBrains）。
- **本质**：它就是「03-Agent核心原理」里那个 Agent Loop 的工业级实现，外加一整套工程化能力。

### 1.2 什么是 Harness

- **定义**：**Agent Harness** = 运行 Agent 循环的**运行时编排框架**。它不是模型本身，而是模型外面的那层「壳」，负责把模型变成一个真正能干活的 Agent。
- **类比**：模型是「大脑」，Harness 是「身体+神经系统+手脚」--负责组装上下文、调度工具、管理记忆、控制权限、跑循环。
- **职责清单**：
  1. 运行 Agent Loop（接收输入->组装上下文->调模型->分发工具->回灌结果）。
  2. 上下文工程（窗口管理、自动压缩、关键信息锚定）。
  3. 工具系统（内置工具、MCP 扩展、工具调度）。
  4. 权限与沙箱（确认、白名单、隔离执行）。
  5. 子 Agent / 并行编排（Task、Workflow）。
  6. 记忆与持久化（memory、todo、文件状态）。
  7. 生命周期（Hooks、计划模式、定时任务）。

> ⚠️ 面试金句：**Agent 的差异往往不在模型，而在 Harness**。同样的模型，Harness 差则 Agent 笨拙易失控；Harness 强则上下文干净、工具顺、能自我修正、能并行扩展。Harness 工程能力是 Agent 厂商的核心壁垒。

## 二、Agent Loop 的真实运行

Claude Code 的核心就是一个被 Harness 驱动的循环：

```
用户输入
   │
   ▼
[组装上下文] 系统提示 + CLAUDE.md项目说明 + 记忆 + 工具说明 + 历史对话 + 文件状态
   │
   ▼
[调模型] LLM 输出：文本 / 工具调用 / 思考
   │
   ├── 若工具调用 ──> [权限检查] ──> [执行工具] ──> 结果作为Observation回灌 ──┐
   │                                                                       │
   └── 若给出最终回答 ──> 输出给用户，本轮结束                                │
   │                                                                       │
   └───────────────────────────────────────────────────────────────────────┘
                              (回到组装上下文，继续循环)
```

关键点：
- **工具调用是循环的引擎**：只要模型还在调工具，循环就继续；模型给出最终文本回答且无工具调用，本轮结束。
- **Observation 回灌**：工具结果不是给用户看的，是放回上下文给模型继续推理的。
- **防死循环**：设最大步数/超时/上下文上限兜底。

## 三、上下文工程实战

Claude Code 把「03-Agent核心原理」的上下文工程落得很实：

### 3.1 上下文窗口管理 + 自动压缩（Auto-Compact）

- 当对话变长、上下文逼近窗口上限时，Harness 自动触发**压缩**：把较早的对话总结成摘要，保留要点，腾出空间继续工作。用户也可手动 `/compact`。
- **关键信息锚定**：系统提示、`CLAUDE.md`（项目级指令）、当前任务目标等始终保留，不被压缩丢掉。
- **会话总结续接**：上下文被压缩后，摘要 + 未压缩部分一起进入下一个窗口，工作不中断。

### 3.2 子 Agent 隔离（Task）

- 把一个子任务交给**子 Agent**，子 Agent 用**独立的上下文**处理（不污染主上下文），只把**最终结论**回传主 Agent。
- 价值：大搜索/大读取产生的海量中间细节被隔离在子上下文里，主上下文保持干净，避免爆炸和注意力稀释。
- 这正是「03」里「隔离（Isolate）」动作的工程实现。

### 3.3 多 Agent 并行（Workflow）

- 用 **Workflow** 机制可并行编排多个子 Agent（如多个维度并行 Review、多文件并行迁移），汇总结果。
- 结合 budget 控制（token 预算）、pipeline/parallel 调度，是「04-多Agent架构」编排流水线模式的真实落地。

## 四、工具系统

### 4.1 内置工具
Claude Code 自带一组工程化工具：
- **文件**：Read / Write / Edit（精确字符串替换）。
- **搜索**：Grep（ripgrep）/ Glob（文件模式匹配）/ 智能符号搜索。
- **执行**：Bash（跑命令，沙箱内）。
- **任务**：Task（子 Agent）、Workflow（多 Agent 编排）、TaskCreate/Update（todo）。
- **记忆**：Write/Read 到 memory 目录。
- **计划**：EnterPlanMode / ExitPlanMode。

### 4.2 MCP 扩展
- 通过 MCP 接入外部工具/数据源（数据库、Figma、Playwright、内部 API），即「06-协议生态」的真实使用。MCP Server 暴露的 Tools 自动进入工具列表供模型调用。

### 4.3 工具调度要点（工程经验）
- **描述即接口**：模型靠工具描述选工具，描述不清就会用错。
- **按需加载（Skill）**：工具太多会注意力稀释，用 Skill 机制按需展开。
- **权限前置**：危险工具（删除/外发/提交）需用户确认。

## 五、Skill 机制（落地）

- Claude Code 内置 **Skill**：可复用、按需加载的能力包（指令 + 脚本 + 资源）。
- **渐进式披露**：平时只有 Skill 名字+一句话描述在上下文，模型判断需要时才加载完整内容，用完释放。省 token、减干扰、可扩展。
- 用户也可自定义 Skill 或通过插件安装。这是「05-Agent开发框架」Skill 概念的真实实现。

## 六、权限与沙箱（安全核心）

### 6.1 权限模式
- **确认机制**：危险操作（写文件、跑命令、删数据、外发请求）默认需用户确认；用户可配置白名单/自动放行规则。
- **权限可降级也可提权**：默认沙箱内运行，需要更高权限时显式请求。

### 6.2 沙箱隔离
- Bash 命令在**沙箱**内执行，限制文件系统访问范围、网络访问，防止误删/越权。
- **外发需确认**：把内容发到外部服务（发布/上传）会被视为「发布行为」，需用户授权，且提示可能被缓存/索引。

### 6.3 数据安全
- 优先读本地、不外传；敏感操作留痕可审计。
- 与「08」的内容审核/权限管理/数据隐私呼应。

## 七、Hooks 与生命周期

- **Hooks**：在工具调用前后、会话事件等生命周期点插入自定义逻辑（如自动 lint、自动测试、注入上下文、记录审计）。
- **计划模式（Plan Mode）**：先调研探索、产出方案给用户审批，批准后再动手--实现「人在环」把控方向。
- **TodoList**：复杂任务拆成可勾选清单，跟踪进度。
- **定时任务（Cron）**：可调度周期性任务，是 Loop 范式在时间维度的延伸。

## 九、常见面试题

1. **什么是 Harness？它和 LLM 是什么关系？**
   Harness 是运行 Agent 循环的运行时编排框架（组装上下文、调度工具、管理记忆、控制权限、跑循环）。模型是大脑，Harness 是身体+神经系统+手脚。Agent 能力差异很大程度在 Harness 而非模型。

2. **Claude Code 的 Agent Loop 是怎么转的？**
   组装上下文->调模型->若工具调用则检查权限执行后把结果作为 Observation 回灌继续循环->若给出最终回答则结束。工具调用是循环引擎，设上限防死循环。

3. **上下文快满了，Harness 怎么处理？**
   自动压缩（Auto-Compact）把旧对话总结成摘要腾空间，关键信息（系统提示/CLAUDE.md/任务目标）锚定保留，子任务用子 Agent 独立上下文隔离只回传结论。

4. **子 Agent / Task 解决什么问题？**
   大搜索/大读取会产生海量中间细节，灌回主上下文会污染+超限。子 Agent 用独立上下文处理，只回传最终结论，保持主上下文干净。是上下文「隔离」动作的实现。

5. **Skill 机制解决什么？为什么比一次性塞所有工具好？**
   工具全塞会上下文爆炸+注意力稀释。Skill 按需加载（渐进式披露），平时只放索引，需要才展开完整指令和资源，省 token、提准确、可扩展。

6. **权限和沙箱怎么保障安全？**
   危险操作需确认、白名单可控、Bash 在沙箱内限制文件/网络访问、外发操作视为发布需授权、敏感操作留审计。

7. **MCP 在 Claude Code 里怎么用？**
   通过 MCP Client 连接外部 MCP Server，Server 暴露的 Tools 自动进入工具列表供模型调用，把「Agent 接工具」标准化、即插即用。

8. **为什么说 Agent 的差异在 Harness？**
   同样模型，Harness 强则上下文干净、工具顺、能自我修正、能并行扩展、安全可控；Harness 弱则易失控、易超限、易误操作。Harness 工程能力是核心壁垒。
